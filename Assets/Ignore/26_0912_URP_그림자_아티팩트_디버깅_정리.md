# URP 툰 셰이더 그림자 아티팩트 디버깅 — 문제 해결 과정 정리

**프로젝트**: MouseAndCheeseGame (Unity 6 / URP)
**날짜**: 2026-09-12
**증상**: 카메라를 움직이면 주방 씬의 벽에 그림자가 계속 흔들리거나, 실제 가구 형태와 무관한 계단(지그재그) 모양의 이상한 그림자가 나타났다 사라짐

---

## 1. 배경

Cel-shading(툰 셰이딩) 커스텀 HLSL 셰이더(`ToonLit.shader`)와 화면 전체에 적용되는 외곽선 포스트프로세스(`ToonOutlineFullScreen.shader` + `FullScreenPassRendererFeature`)를 URP에 직접 구현한 뒤, 주방 씬(싱크대·오븐·냉장고·식탁)에서 카메라를 움직일 때마다 벽면 그림자가 부자연스럽게 바뀌는 문제가 발견됐다.

증상은 한 가지가 아니라 **여러 개의 서로 다른 원인이 겹친 문제**였고, 각각을 분리해서 진단하는 데 상당한 시행착오가 있었다.

---

## 2. 1차 증상: 카메라를 움직이면 그림자가 깨짐

### 시도했지만 아닌 것으로 판명된 가설들

| 가설 | 검증 방법 | 결과 |
|---|---|---|
| Shadow Distance / Cascade 설정 | 설정값 검토 | 사용자 판단으로 기각 |
| Soft Shadow(PCF)의 디더링이 2단계 밴딩과 충돌 | `ToonLit.shader`에서 `_SHADOWS_SOFT` 변형 제거 | 관련 없다고 판단, 이후 원복 |
| 외곽선 포스트프로세스의 depth/normal edge detection이 원흉 | `FullScreenPassRendererFeature`를 껐다 켜서 A/B 비교 | **artifact가 사라짐을 확인** → 유력 용의자로 지목 |

### 외곽선 셰이더 수정 시도 (실패)

Raw depth 비교를 `LinearEyeDepth`로 바꾸는 두 가지 방식(절대값 변환, 상대/비례 변환)을 시도했으나 **오히려 화면 곳곳에 거대한 검은 영역이 생기는 더 심각한 회귀**가 발생했다. 두 시도 모두 롤백하고 셰이더를 원본 상태로 복원.

### 실제 해결

**Shadow Max Distance 값을 올리는 것으로 해결됨.** 원인은 카메라가 러너 게임 특성상 전방으로 이동하면서, 이전에 설정된 Shadow Distance보다 먼 지점의 오브젝트가 시야에 들어오는데 그 지점은 그림자 계산 범위 밖이라 그림자가 Distance 경계를 넘나들며 깜빡였던 것.

→ **교훈**: 겉보기엔 같은 "카메라 움직이면 그림자 이상해짐" 증상이라도 원인은 포스트프로세스 셰이더, 라이트 세팅 등 전혀 다른 레이어에 있을 수 있다. 눈에 보이는 현상만으로 성급하게 셰이더 코드를 고치기보다, 기능을 하나씩 끄고 A/B 비교하는 게 훨씬 안전했다.

---

## 3. 2차 증상: 벽에 계단(지그재그) 모양의 정체불명 그림자

Shadow Distance 문제를 해결한 뒤에도, 벽에 실제 가구 실루엣과 무관한 **계단 모양의 그림자**가 남아있었고, 이번엔 카메라 "거리"에 따라 나타났다 사라지는 패턴이었다.

### 시도 1: 그림자를 아예 라이트맵으로 베이크

정적인 그림자를 고정시키기 위해 다음을 적용:

- `Kitchen` 하위 오브젝트(싱크대/오븐/냉장고/식탁/의자/벽/바닥) 전체를 **Static (Contribute GI)** 로 표시
- 움직이는 캐릭터(쥐/고양이)는 Static 제외, 계속 실시간 그림자 유지
- Directional Light를 **Mixed 모드**로 전환
- Lighting Settings를 새로 생성해 **Mixed Lighting Mode = Shadowmask**로 설정
- `bake_lighting` 실행 (Progressive GPU, 약 84초, 라이트맵 7장 생성)

**결과**: 기존의 크고 복잡한 이중 지그재그 모양은 사라졌지만, 작은 스파이크 형태의 그림자가 여전히 남아있었고 여전히 카메라 거리에 따라 변했다. → 부분적 개선에 그침.

### 시도 2: 원인 오브젝트 특정 (체계적 A/B 테스트)

씬의 모든 Renderer를 머티리얼별로 분류(Sink_Mat / Oven_Mat / refrigerator_Mat / Table&Chair_Mat / Wall_Mat / Rat_Mat / Cat_Mat)한 뒤, **Unity CLI(`unity command eval`)로 각 그룹의 `shadowCastingMode`를 껐다 켜며 Scene View 스크린샷을 비교**하는 방식으로 원인을 좁혀나갔다.

- 개별 그룹(싱크대, 오븐, 냉장고, 벽, 식탁&의자)을 하나씩 꺼봐도 그림자는 사라지지 않음
- 두 그룹을 조합(오븐+식탁&의자 등)해도 사라지지 않음
- **Kitchen 하위 모든 오브젝트를 한꺼번에 끄면 사라짐** → 특정 오브젝트 하나의 문제가 아니라는 결론
- 라이트의 `shadows`를 완전히 `None`으로 끄면 즉시 사라짐 → **실시간 그림자 자체의 렌더링 문제**라고 특정

### 근본 원인 발견: Shadow Cascade 경계선

URP Directional Light는 카메라로부터의 거리에 따라 그림자를 여러 단계(Cascade)로 나눠 각기 다른 해상도로 렌더링한다. 이 씬은:

- `shadowDistance = 150`
- `cascadeCount = 4`
- 기본 분할 비율 `(0.12, 0.29, 0.54)` → 첫 Cascade 경계가 약 **18유닛** 지점

그런데 주방(싱크대~냉장고~뒷벽)은 카메라로부터 대략 **20~50유닛** 범위에 걸쳐 있어, 정확히 이 경계선 위에 걸쳐 있었다. 경계에 걸친 지오메트리는 카메라 거리가 바뀔 때마다 서로 다른 정밀도의 Cascade로 번갈아 렌더링되며 그림자 가장자리가 들쭉날쭉 흔들린다. 개별 오브젝트를 꺼도 사라지지 않았던 이유도 이것으로 설명된다 — 문제는 특정 가구가 아니라 **그 영역 전체가 Cascade 경계에 걸쳐있다는 것** 자체였다.

### 최종 해결

URP Asset의 `cascade4Split`을 `(0.12, 0.29, 0.54)` → **`(0.4, 0.6, 0.8)`** 로 조정. 첫 Cascade가 0~60유닛을 커버하게 되어 주방 전체가 경계 없이 하나의 Cascade 안에 들어가도록 함. 카메라를 가깝게/멀게 여러 거리에서 테스트한 결과 완전히 해결됨을 확인.

## 4. 최종 설정 요약

| 항목 | 값 |
|---|---|
| Shadow Distance | 150 |
| Cascade Count | 4 |
| Cascade Split | (0.4, 0.6, 0.8) |
| Shadow Depth/Normal Bias | 기본값 (0.1 / 0.5) |
| Main Light Shadow Resolution | 2048 |
| Directional Light Mode | Mixed |
| Mixed Lighting Mode | Shadowmask |
| 정적 오브젝트 | Kitchen 하위 전체 Static(Contribute GI) |

## 5. 배운 점

1. **같은 증상 ≠ 같은 원인.** "카메라 움직이면 그림자가 이상해진다"는 증상 하나에 Shadow Distance, 외곽선 포스트프로세스, Shadowmask/베이크, Cascade 경계선까지 최소 4개의 서로 다른 레이어가 관련되어 있었다.
2. **추측으로 셰이더 코드를 고치는 것은 위험하다.** Depth 비교 로직을 두 번 고쳤지만 둘 다 기존 문제보다 더 큰 회귀(화면 전체가 검게 나오는 등)를 만들었다. 반면 기능을 끄고 켜는 A/B 테스트는 항상 안전하게 원인을 좁혀줬다.
3. **오브젝트 단위 A/B 테스트의 함정.** 개별 오브젝트/머티리얼 그룹을 하나씩 꺼보는 이분탐색은 "특정 오브젝트가 원인"인 버그에는 잘 맞지만, 이번처럼 **특정 공간 영역 자체가 문제(Cascade 경계)**인 경우에는 오브젝트를 아무리 조합해서 꺼봐도 명확한 답이 안 나올 수 있다. 이럴 땐 "라이트 자체를 꺼서 완전히 사라지는지"처럼 더 상위 레벨에서 이분탐색하는 게 힌트가 됐다.
4. **라이트맵 베이크가 만능은 아니다.** 정적 오브젝트를 베이크하면 실시간 그림자 문제가 사라질 거라 기대했지만, Shadowmask 모드는 Shadow Distance 이내에서는 여전히 실시간 그림자를 그리기 때문에 근본 원인(Cascade 경계)은 그대로 남아있었다.
5. **Unity CLI(`unity command eval`)로 에디터를 스크립트 삼아 반복 테스트한 것이 효과적이었다.** Scene View 스크린샷을 매번 캡처해서 비교하는 방식으로, 수십 번의 on/off 조합을 사람이 직접 클릭하지 않고도 빠르게 검증할 수 있었다.
