# 점수 랭킹 시스템 (로컬 최고기록 저장 + 실시간 점수 HUD) 기능 매뉴얼

- 작성 날짜: 2026-09-23 (26_0923)
- 작성자: builder (Claude Code)
- 참고 계획 파일: `Assets/Ignore/Task/Plan/26_0923_점수랭킹시스템_plan.md` (2절, 3절, 4-1~4-5절 코드 스니펫 그대로 구현)
- 구현 범위: 코드 5개 파일(신규 4, 수정 1). Unity Editor 수동 작업(계획서 4-6절)은 코드 구현 범위가 아니라 아래 3절에 절차만 정리했다.
- **Unity 컴파일과 Play 검증은 하지 못했다.** 이 환경에서는 Unity Editor를 실행할 수 없어 코드 대조 확인만 했다.

## 1. 기능 요약

플레이어가 생존한 시간과 먹은 음식(사과·치즈)을 합산해 점수를 계산하고, 게임오버 시 로컬 최고기록과 비교·저장한 뒤 게임오버 화면에 이번 판 점수·최고기록·신기록 여부를 표시한다. 플레이 중에는 항상 실시간 점수 HUD가 보인다.

- **점수 지표**: 이동 거리가 아니라 **생존시간**(`Time.deltaTime` 누적)이다. 초당 1점, 사과 섭취 시 30점, 치즈 섭취 시 60점(전부 임시 밸런싱 값, `ScoreData` 에셋에서 조정 가능).
- **장애물 섭취**: 점수에 전혀 영향을 주지 않는다(감점 없음, 계획서 0-1절 확정).
- **게임오버 트리거**: 기존 `CatController.OnPlayerCaught` 이벤트를 그대로 재사용한다. `GameOverUI`와 `ScoreController`가 이 이벤트를 각자 독립적으로 구독하며, 두 컴포넌트 모두 수정하지 않았다.
- **음식 소비 감지**: `Food.cs`에 정적 이벤트 `OnAnyConsumed`를 추가해, 어느 `Food` 인스턴스든 소비되면(기존 인스턴스 이벤트 `OnConsumed`와 별개로) 전역에서 감지할 수 있게 했다. `ObjectSpawner.cs`는 전혀 수정하지 않았다.
- **경쟁 상태 방지**: `ScoreResultUI`는 `CatController.OnPlayerCaught`를 직접 구독하지 않고, `ScoreController`가 최고기록 비교·저장까지 마친 뒤에만 발생시키는 `OnScoreFinalized` 이벤트만 구독한다. 이렇게 해야 구독 순서와 무관하게 항상 최종 확정된 점수·최고기록을 읽는다.
- **최고기록 저장**: `PlayerPrefs.SetInt("MouseAndCheese_HighScore", ...)`로 저장하고, `Awake()`에서 `PlayerPrefs.GetInt`로 불러온다. 씬 리로드(재시작)에도 값이 유지된다.
- **신기록 연출**: `IsNewHighScore`가 true일 때만 `_newRecordBadge.SetActive(true)`를 호출하는 최소 구현이다. 애니메이션·사운드·색상 등 구체적 연출은 넣지 않았다(계획서 0-4절, 사용자가 에디터에서 직접 추가해야 함).
- **최고기록 리셋 기능**: 구현하지 않았다(계획서 0-2절, 미확정 사항으로 남김).
- **점수 표시 형식**: 천 단위 구분 기호 등 없이 `int.ToString()` 그대로 표시한다(계획서 0-3절).

## 3. Unity Editor에서 사용자가 직접 해야 할 수동 작업

코드만으로는 씬에서 동작하지 않는다. 계획서 4-6절 그대로, 아래를 Unity Editor에서 순서대로 수행해야 한다(코드 구현 범위 밖이라 직접 하지 않았다).

1. **`ScoreData` 에셋 생성**: `Assets/05_Data`에서 우클릭 → Create → MouseAndCheese → Score Data. 기본값(생존 1점/초, 사과 30점, 치즈 60점) 그대로 임시로 쓴다.
2. **`Food.cs` 수정 확인**: 이미 사용자 승인에 따라 반영 완료(2절 참고). 별도 작업 불필요.
3. **`Player`(씬 인스턴스, `HungerController`/`PlayerPathRecorder`가 부착된 오브젝트)에 `ScoreController` 컴포넌트 추가**하고 다음을 연결한다.
   - `_catController`: 씬의 `Cat` 인스턴스(기존 `GameOverUI`/`GapDistanceUI`의 `_catController`와 동일한 대상)
   - `_scoreData`: 1번에서 만든 에셋
4. **`GameOver` 패널**(`Assets/01_Scenes/02_Ingame.unity`, 현재 `Re_Button`/`Quit_Button`만 있음) **하위에 TMP 텍스트 오브젝트 2개**(`Score_Text`, `HighScore_Text`)**와 신기록 배지 오브젝트 1개**(예: `NewRecord_Text`)**를 새로 만든다.** 기존 `Text (TMP)` 오브젝트들과 동일한 폰트(`LiberationSans SDF`)를 사용한다. `NewRecord_Text`는 시작 시 비활성(`SetActive(false)`) 상태로 둔다 — `ScoreResultUI`가 신기록일 때만 켠다.
5. **`Canvas` 루트(또는 `GameOverUI`가 부착된 것과 같은, 항상 활성 상태인 오브젝트)에 `ScoreResultUI` 컴포넌트를 추가**하고 다음을 연결한다. **`GameOver` 패널 자체는 시작 시 비활성이므로 그 하위에 붙이면 안 된다**(경쟁 상태 방지, 2절 근거).
   - `_scoreController`: 3번에서 추가한 `ScoreController`
   - `_scoreText`: 4번에서 만든 `Score_Text`
   - `_highScoreText`: 4번에서 만든 `HighScore_Text`
   - `_newRecordBadge`: 4번에서 만든 `NewRecord_Text`
6. **`Canvas` 루트(`HungerGaugeUI`/`GapDistanceUI`와 같은 위치)에 TMP 텍스트 오브젝트**(예: `Score_HUD_Text`)**를 새로 만들고 `ScoreHUD` 컴포넌트를 부착**한 뒤 `_scoreController`를 3번에서 추가한 `ScoreController`로 연결한다.

## 4. 동작 확인 방법 (Play 모드, 사용자가 직접 확인)

1. **실시간 HUD**: 플레이 시작 직후부터 `Score_HUD_Text`가 매초 값이 오르는지 확인한다.
2. **음식 보너스**: 사과를 먹으면 점수가 30 오르고, 치즈를 먹으면 60 오른다. 쥐덫(장애물)을 밟아도 점수는 변하지 않는다(배고픔만 감소).
3. **게임오버 표시**: 고양이에게 잡히면 `GameOver` 패널이 뜨면서 `Score_Text`(이번 판 점수)와 `HighScore_Text`(최고기록)가 동시에 채워진다.
4. **신기록 배지**: 최고기록을 갱신한 판에서만 `NewRecord_Text`가 나타난다. 갱신하지 못한 판에서는 비활성 상태를 유지한다.
5. **영속성**: `RestartGame()`으로 씬을 재시작(`Re_Button`)하거나 에디터 플레이를 껐다 켜도 이전 최고기록이 유지되는지 확인한다(`PlayerPrefs` 키 `MouseAndCheese_HighScore`).
6. **경쟁 상태 재확인**: 게임오버 순간 `Score_Text`/`HighScore_Text`가 갱신 전(stale) 값 없이 항상 올바른 최종값으로 채워지는지(특히 신기록을 세운 판에서 `HighScore_Text`가 이번 판 점수와 같은 값으로 즉시 갱신되는지) 확인한다.

## 5. 검증하지 못한 부분

- **Unity 컴파일을 하지 못했다.** `TMP_Text`, `CatController.OnPlayerCaught`, `Food.HungerObjType`, `PlayerPrefs` API는 기존 코드에서 이미 쓰이고 있는 것과 동일한 시그니처로만 사용했으나, 실제 컴파일 확인은 사용자가 Unity Editor에서 해야 한다.
- **Play 검증을 하지 못했다.** 점수 누적 정확도, 신기록 배지 타이밍, `PlayerPrefs` 영속성은 모두 사용자가 확인해야 한다.
- **씬/에셋 작업**: `ScoreData.asset` 생성, `ScoreController`/`ScoreResultUI`/`ScoreHUD` 컴포넌트 부착과 필드 연결, `GameOver` 패널 하위 TMP 텍스트·배지 오브젝트 생성은 전부 미수행이다(3절 참고, 계획서 자체가 이를 "코드 외 수동 작업"으로 분류했다).

## 6. 확정되지 않아 임의로 결정하지 않은 사항 (계획서 0절 그대로 유지)

- **장애물 섭취 시 감점 여부**: 감점 없음으로 구현(계획서 0-1번).
- **최고기록 초기화(리셋) 기능**: 구현하지 않음(계획서 0-2번).
- **점수 표시 형식**: `ToString()` 그대로, 천 단위 구분 없음(계획서 0-3번).
- **NEW RECORD 연출의 구체적 형태**: `SetActive` 토글까지만 구현. 애니메이션·사운드·색상 등은 사용자가 에디터에서 직접 추가해야 한다(계획서 0-4번).

## 8. 롤백 방법

`Assets/02_Scripts/Score/` 폴더를 삭제하고, `Food.cs`에서 추가한 `public static event Action<Food> OnAnyConsumed;` 선언과 `OnAnyConsumed?.Invoke(this);` 호출 한 줄을 제거한다. 에디터 작업(3절)을 진행했다면 `ScoreData.asset`, 씬에 추가한 `ScoreController`/`ScoreResultUI`/`ScoreHUD` 컴포넌트와 신규 TMP 오브젝트들도 함께 되돌린다. `PlayerPrefs` 키(`MouseAndCheese_HighScore`)는 코드 롤백만으로는 지워지지 않으므로, 초기화가 필요하면 별도로 `PlayerPrefs.DeleteKey`를 호출하거나 에디터의 Clear All PlayerPrefs를 사용해야 한다.
