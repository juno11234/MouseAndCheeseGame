## 1. 기능 요약

고양이 AI의 거리 계산을 "플레이어 누적 이동 거리 - 고양이 누적 이동 거리"(오도미터 차) 추정치에서 실측 직선거리(3D, 수직 성분 포함)로 바꾸고, 포획(게임오버 조건) 판정을 `Gap <= 0`에서 고양이 트리거 충돌로 바꿨다.

- **갭(`CatController.Gap`)**: `Vector3.Distance(고양이 위치, 플레이어 위치)`. 상태가 없는 순수 측정값이며 읽을 때마다 계산한다. 스냅샷 저장과 `OnGapChanged` 인자처럼 실제 거리 값이 필요한 곳에서만 쓴다.
- **임계값 비교(`IsWithinGap(float distance)`)**: `(고양이 위치 - 플레이어 위치).sqrMagnitude <= distance * distance`. 제곱근 없이 비교한다. 다음 세 곳이 사용한다.
  - `Chasing` -> `DirectChasing` 전환: `IsWithinGap(DirectChaseDistance)`
  - `DirectChasing` -> `Chasing` 전환: `IsWithinGap(DirectChaseDistance) == false`
  - 러버밴딩: `IsWithinGap(MaxGap)`이면 `MoveSpeed`, 아니면 `RubberBandSpeed`
  - 풀잎 비행 후 복원: `GapCorrecting`에서 `IsWithinGap(비행 전 갭 + GapCorrectionTolerance)`이면 `Chasing` 복귀(단방향 비교)
- **경로점 기록 간격(`PlayerPathRecorder.ResolveFrameInterval`)**: 동작은 이전과 같다. 고양이와의 제곱 거리가 `_farDistance` 제곱 이상이면 제곱근 없이 `_farFrameInterval`을 바로 반환하고, 그 미만에서만 제곱근으로 보간 비율을 구한다.
- **경로점 도착 판정**: 변경 없음. `NavMeshAgent.remainingDistance <= WaypointArrivalTolerance`를 그대로 쓴다(계획서 0-3 확정).
- **충돌 포획**: `CatController.OnTriggerEnter(Collider other)`가 감지한다. `Frozen`(비행 중)·`Caught` 상태에서는 무시하고, 그 외 상태에서 `other.TryGetComponent(out Player _)`가 성공하면 `SetState(CatState.Caught)` 후 `OnPlayerCaught`를 한 번 발생시킨다. `Caught` 상태 자체가 한 번만 발생시키는 가드이므로 `_hasGapDepleted`는 삭제했다. 게임오버 UI 등 이후 처리는 이 이벤트를 구독할 별도 Feature 책임이다.
- **비행 중 고양이 애니메이션**: `SetState`가 Animator의 bool `Run`을 `newState != CatState.Frozen`으로 설정한다. 비행 시작(`Frozen`)에서 false(Idle), 착지 후 `GapCorrecting` 진입에서 true(Walk)로 돌아온다. `Caught`에서는 true를 유지한다(계획서 0-7 (b) 임시 처리). Animator는 자식 `Cat_Model`에 있어 `Awake`에서 `GetComponentInChildren<Animator>()`로 찾는다.
- **비행 중 경로 기록 중단/재개**: 기존 동작 그대로다(`PlayerPathRecorder`가 `Fly` 중 기록하지 않고 `Run` 복귀 시 재개).
- **삭제된 것**: `TotalPathDistance`, `_lastPosition`, `_totalPathDistance`, `_catTraveledDistance`, `TrackTraveledDistance`, `_hasGapDepleted`, `DistanceToPlayer`, `OnGapDepleted`/`GapDepletedHandler`, `_initialGap`/`InitialGap`/`[Header("초기 상태")]`.

## 3. Unity Editor에서 사용자가 직접 해야 할 수동 작업

코드만으로는 충돌 포획이 동작하지 않는다. 아래를 Unity Editor에서 수행해야 한다(코드 구현 범위 밖이라 직접 하지 않았다).

1. **`Assets/4_Prefabs/Cat.prefab`을 열어 프리팹 레벨에서 작업한다**(씬 인스턴스가 아니라 프리팹). Cat 루트 GameObject에 아래 두 컴포넌트를 추가한다.
   - `Rigidbody`: Is Kinematic ON, Use Gravity OFF, 나머지는 기본값.
   - `CapsuleCollider`: Is Trigger ON, Direction Y-Axis, Radius 0.5, Height 2, Center (0, 1, 0).
   - 위 콜라이더 치수는 NavMeshAgent 반지름 0.5 · 높이 2를 그대로 옮긴 자리 표시자다(계획서 0-5 (b) 미확정). 씬 뷰에서 고양이 모델과 크기를 비교해 조정한다. 콜라이더 높이는 "플레이어가 고양이 위로 점프해 피할 수 있는가"를 결정한다.
2. **Cat의 레이어는 Default(0)를 유지한다.** `CameraCollision`(6번) 레이어로 바꾸면 `Physics.queriesHitTriggers`가 켜져 있어 Player의 접지 SphereCast와 카메라 충돌 캐스트가 Cat의 트리거에 걸린다.
3. **Console에서 컴파일 오류가 없는지 확인한다.** `Assets/02_Scripts` 전체를 검색해 삭제된 이름(`OnGapDepleted`, `TotalPathDistance`, `InitialGap` 등)의 잔존 참조가 없음을 확인했다.
4. **`CatStatData.asset`은 직접 고치지 않는다.** 에셋에 남은 `_initialGap: 5`는 스크립트에 필드가 없으므로 Unity가 무시하며, 에셋을 다시 저장할 때 사라진다.
5. **Cat의 Animator 컨트롤러(`Char_AniController 1.controller`)에는 bool `Run`이 이미 있어** 추가 작업이 없다. 컨트롤러를 다른 것으로 바꾼다면 같은 이름의 `Run` bool 파라미터가 있어야 한다.
6. 씬 인스턴스 오버라이드와 `NavMeshSurface` 재베이크는 필요 없다.
7. (선택) 시작 거리를 바꾸려면 `SampleScene.unity`에서 Cat 또는 Player의 초기 위치를 조정한다. 이제 초기 거리는 씬 배치가 유일한 출처다.

## 4. 동작 확인 방법 (Play 모드, 사용자가 직접 확인)

기존 `Debug.Log(_state)`로 상태 전환을 볼 수 있다.

1. **게임 시작 직후**: 즉시 `Caught`가 되지 않는다. `Gap`은 씬 배치 거리(약 21.7m)로 시작하고 `MaxGap`(15)보다 커서 첫 경로점을 받은 뒤 러버밴딩 속도로 움직인다.
2. **직접 추격 진입/이탈**: `Gap <= 10`에서 `DirectChasing`, `Gap > 10`에서 `Chasing`. 이탈 시 큐가 비워진다.
3. **러버밴딩**: `Gap > 15`인 `Chasing`에서 에이전트 속도 8, 그 아래에서 4.
4. **충돌 포획**: 플레이어가 멈추고 고양이가 접근해 트리거가 플레이어에 겹치면 `Caught`로 바뀌고 에이전트가 멈추며 `OnPlayerCaught`가 정확히 한 번 발생한다(현재 구독자가 없어 임시 로그 구독으로 확인). 포획 순간 `Gap`은 0이 아니라 트리거 반지름 + 플레이어 반지름(0.25) 정도다. 저프레임에서 스치는 접근도 포획되는지 함께 본다. **`OnTriggerEnter`가 발생하지 않으면**(kinematic Rigidbody 트리거와 CharacterController 조합 미검증) 계획서 6-9절의 물리 쿼리 폴링 대안으로 전환한다.
5. **바닥·가구 겹침**: Cat이 바닥·가구 콜라이더와 겹쳐도 포획이 발생하지 않는다.
6. **플레이어 쪽 영향 없음**: 풀잎 비행 시작, 음식·함정 배고픔 변화, 접지 판정(고양이 근처 점프 횟수 리셋), 카메라 충돌이 Cat 트리거의 영향을 받지 않는다.
7. **도달 불가 경로점**: 링크 없는 가구 위나 점프 중 공중에서 기록된 경로점이 목표가 돼도 고양이가 그 자리에서 영구히 멈추지 않고 다음 경로점으로 넘어가는지 본다(`remainingDistance` 판정 유지의 검증 사항).
8. **풀잎 비행 후 복원**: 제자리 비행 후 착지하면 `GapCorrecting`이 거의 즉시 끝난다. 전진 비행 후 착지하면 고양이가 보정 속도로 달려 `Gap <= 비행 전 Gap + 0.1`이 되는 순간 `Chasing`으로 돌아온다. 싱크대 위 착지 같은 도달 불가 위치에서 `GapCorrecting`에 머무는지 관찰한다.
9. **비행 중 포획 무시**: 비행 중(`Frozen`) 고양이 위를 지나가도 포획되지 않는다. `GapCorrecting` 중 겹치면 포획된다.
10. **비행 중 애니메이션**: 비행 시작 시 고양이가 정지하고 Animator가 Idle(`Run` false)이 되며, 착지 후 `GapCorrecting` 진입 시 Walk(`Run` true)로 돌아온다. `QueuedPointCount`로 비행 중 경로점 기록이 멈추고 착지 후 다시 늘어나는지 확인한다.

## 5. 확정되지 않아 이번 구현에서 임의로 결정하지 않은 사항 (계획서 0절 그대로 유지)

- **트리거 콜라이더 크기·위치**(0-5 (b)): 자리 표시자 치수. 고양이 시각 크기와 맞게 사용자가 조정한다.
- **Rigidbody 방식 검증**(0-5 (c)): kinematic Rigidbody 트리거와 CharacterController 사이의 `OnTriggerEnter` 도달은 실행해 확인하지 못했다.
- **포획 상태 범위**(0-5 (d)): `Chasing`, `DirectChasing`, `GapCorrecting`에서 포획, `Frozen`·`Caught`에서 무시.
- **`OnTriggerEnter`만 쓰는 한계**(0-5 (f)): 진입 시점에 `Frozen`이면 그 진입은 무시되고, 겹친 채로 `Frozen`이 풀려도 나갔다 다시 들어오기 전에는 포획이 발생하지 않는다.
- **`GapCorrecting` 갇힘 위험**(0-4): 플레이어가 링크로 연결되지 않은 곳에 착지하면 갭이 `snapshot + tolerance` 아래로 내려가지 않아 `GapCorrecting`에 머물 수 있다. 이 상태에서는 직접 추격과 러버밴딩이 꺼져 있고 타임아웃이 없다. 또 플레이어 최고 속도(10)와 보정 속도(10)가 같아 최고 속도로 달리면 거리가 줄지 않는다.
- **`Caught`에서 애니메이션**(0-7 (b)): `Caught`에서는 `Run`을 true로 유지한다.
- **수치 의미 변화**(0-6): 값은 그대로이나 갭이 직선거리가 되어 `_maxGap`(15) < 씬 시작 거리(21.7m)이므로 시작부터 러버밴딩 조건이 성립한다. `_directChaseDistance`(10)와 `_maxGap`(15)이 같은 거리 척도에서 만난다. 우회로가 긴 경로에서는 러버밴딩이 예전보다 덜 발동한다. `_gapCorrectionTolerance`(0.1)는 "허용 구간 폭"이 아니라 "스냅샷에 더하는 여유"가 됐다. 값 조정은 플레이테스트 후 별도로 다룬다.
- **범위 밖 유지**: 리뷰 항목 R3(직접 추격 경계 진동), B1(`Debug.Log` 3곳) 등은 이번에 손대지 않았다.
