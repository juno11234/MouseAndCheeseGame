# 카메라 컨트롤러(벽 충돌 방지) 기능 매뉴얼

- 작성 날짜: 2026-08-26 (26_0826)
- 작성자: builder (Claude Code)
- 참고 계획 파일: `Assets/10_ignore/01_Plan/26_0826_카메라컨트롤러_plan.md`

## 1. 기능 요약

좌우 회전 책임을 `Player`에서 신규 `CameraController`(카메라 피벗 오브젝트)로 이전하고, `Player`는 전진 이동만 담당하도록 재설계했다. 또한 `CameraController`가 매 프레임 `Physics.SphereCast`로 벽 등 지오메트리와의 충돌을 검사해, 카메라가 벽을 뚫고 들어가는 클리핑 현상을 방지한다.

- **A / D**: `CameraPivot`(신규 오브젝트, `Player`의 자식)을 Y축으로 좌우 회전시킨다. `Player` 루트 자체는 더 이상 회전하지 않는다.
- **W**: `CameraController.ForwardDirection`(카메라 피벗이 바라보는 수평 방향)으로 `CharacterController.Move()`를 통해 전진한다.
- **S**: 이전과 동일하게 후진 로직 없음 (음수 값은 `Mathf.Max(0f, ...)`로 차단).
- 카메라는 매 `LateUpdate`마다 피벗에서 `SphereCast`를 쏘아 벽에 닿으면 목표 거리를 줄여 `Vector3.SmoothDamp`로 위치를 당겨온다.
- LockOn, Q/E 타겟 전환, 마우스 pitch 조작은 이번 구현 범위에 포함하지 않았다.

## 2. 변경된 파일 목록

| 구분 | 파일 경로 | 내용 |
|---|---|---|
| 신규 | `Assets/02_Scripts/CameraController.cs` | `InputManager.MoveInput.x`로 자신(카메라 피벗)을 Y축 회전시키는 `HandleRotation()`(`Update`에서 호출), `SphereCast` 기반 벽 충돌 회피로 `_cameraTransform.position`을 보정하는 `HandleCollision()`(`LateUpdate`에서 호출), `Player`가 이동 방향 계산에 사용하는 `ForwardDirection` 프로퍼티(피벗의 `transform.forward`를 Y=0 평면에 투영·정규화, 캐싱하지 않고 매 호출 즉시 계산) 제공. `[SerializeField]` 필드: `_inputManager`, `_cameraTransform`, `_rotationSpeed`(180), `_collisionLayerMask`, `_collisionRadius`(0.3), `_collisionBuffer`(0.2), `_minDistance`(0.5), `_cameraSmoothSpeed`(15). |

## 3. Unity Editor에서 사용자가 직접 해야 할 수동 작업

씬 파일(`Assets/01_Scenes/SampleScene.unity`)과 `ProjectSettings`(레이어 추가)는 코드/텍스트로 직접 편집하지 않았다. GUID/fileID 손상 위험을 피하기 위해 아래 절차를 반드시 Unity Editor UI에서 순서대로 직접 수행해야 한다.

### 3-1. 현재 씬 상태 (계획 단계에서 확인된 내용)

```
Player (local pos (0,0,0), rotation identity)
├─ CharacterController, Player.cs, InputManager.cs
├─ Capsule (MeshRenderer + MeshFilter, Collider 없음)
└─ Main Camera (local pos (0, 3.25, -5.35), local rot ≈ X 2.529° tilt)
     └─ Camera(near clip 0.3), AudioListener, UniversalAdditionalCameraData

Kitchen
├─ refrigerator_Prefab 인스턴스 (Collider 없음)
└─ Plane (MeshCollider 보유, 바닥면)
```
레이어는 `Default/TransparentFX/Ignore Raycast/Water/UI`만 정의되어 있고, `Player`/`Wall`/`Environment` 같은 커스텀 레이어는 없다. 벽/가구 Collider가 아직 없으므로 4번 작업(레이어+Collider 추가)을 완료해야 SphereCast 충돌 회피가 실질적으로 동작한다.

### 3-2. 절차

1. **CameraPivot 생성**
   - `SampleScene.unity`를 열고 `Player` GameObject를 선택한 상태에서 `GameObject > Create Empty`(또는 우클릭 → Create Empty)로 빈 오브젝트를 생성해 `Player`의 자식으로 만든다.
   - 이름을 `CameraPivot`으로 변경한다.
   - Inspector에서 Transform을 `Local Position (0, 3.25, 0)`, `Local Rotation (0, 0, 0)`으로 설정한다.

2. **Main Camera 재배치**
   - `Main Camera`(현재 `Player`의 자식)를 Hierarchy에서 드래그하여 `CameraPivot`의 자식으로 이동한다.
   - `Main Camera`의 `Local Position`을 `(0, 0, -5.35)`로 변경한다.
   - `Local Rotation`은 기존 값(약 X 2.529° tilt)을 그대로 둔다(변경하지 않음).
   - 재배치 후 Scene/Game 뷰에서 카메라 위치가 기존과 시각적으로 동일한지(점프 없음) 확인한다.

3. **CameraController 컴포넌트 부착 및 필드 연결**
   - `CameraPivot`을 선택하고 `Add Component` → `CameraController`를 추가한다.
   - `_inputManager`: `Player`에 부착된 `InputManager` 컴포넌트를 드래그하여 연결한다.
   - `_cameraTransform`: 자식 `Main Camera`의 Transform을 드래그하여 연결한다.
   - `_rotationSpeed`: 180 (기존 `Player._turnSpeed`와 동일 값, 필요 시 조정).
   - `_collisionRadius`: 0.3 (Camera의 Near Clip Plane 값과 동일하게 맞춤).
   - `_collisionBuffer`: 0.2, `_minDistance`: 0.5, `_cameraSmoothSpeed`: 15.
   - `_collisionLayerMask`: 아래 4번 작업을 완료한 뒤 설정한다(지금은 비워두거나 Nothing으로 둬도 무방).

4. **(선행 필요) 벽/가구 Collider 및 전용 Layer 추가**
   - `Edit > Project Settings > Tags and Layers`에서 사용하지 않는 User Layer 슬롯에 `Environment`라는 이름의 레이어를 새로 등록한다.
   - Kitchen 하위의 벽/가구 GameObject(예: `refrigerator_Prefab` 인스턴스 및 향후 추가될 벽 지오메트리)에 `BoxCollider` 또는 `MeshCollider`를 추가한다.
   - 해당 GameObject들의 Layer를 방금 만든 `Environment`로 지정한다.
   - `CameraPivot`의 `CameraController` 컴포넌트로 돌아가 `_collisionLayerMask`에서 `Environment` 레이어만 체크한다. `Player`가 속한 `Default` 레이어는 반드시 제외한다(포함 시 SphereCast가 Player 자신의 `CharacterController`를 맞혀 오작동할 수 있다).

5. **Player 컴포넌트 필드 갱신**
   - `Player` GameObject를 선택한다.
   - `Player` 컴포넌트 인스펙터에서 신규로 노출된 `_cameraController` 필드에 `CameraPivot`의 `CameraController` 컴포넌트를 드래그하여 연결한다.
   - 기존 `_turnSpeed` 필드는 코드에서 제거되어 Inspector에서 자동으로 사라진다(재확인만 하면 됨).

6. 모든 연결이 끝나면 씬을 저장한다 (Ctrl+S).

## 4. 테스트 방법

1. Unity Editor에서 `SampleScene`을 Play 모드로 실행한다.
2. `A` / `D` 키를 누르면 화면(카메라 시점)만 좌우로 회전하고, `Player`(캡슐) 자신은 제자리에서 회전하지 않는지 확인한다.
3. `W` 키를 누르면 카메라가 현재 바라보는 방향으로 `Player`가 전진하는지 확인한다. `A`/`D`로 화면을 돌린 직후 `W`를 눌러 화면상 정면 방향으로 정확히 이동하는지 확인한다(카메라 상대 이동).
4. `S` 키만 누르면 아무 이동도 발생하지 않는지 확인한다(후진 없음, 기존과 동일).
5. Kitchen의 벽/가구(Collider + `Environment` 레이어 설정 완료 후)에 카메라 쪽으로 접근시키면서 `A`/`D`로 회전해, 카메라가 벽을 관통하지 않고 앞으로 당겨지는지 확인한다(클리핑 방지 동작 확인).
6. 벽에서 멀어지면 카메라가 다시 원래 거리(`_defaultDistance`, 초기 배치 거리)로 부드럽게 복귀하는지 확인한다.
7. `_collisionLayerMask`에 실수로 `Default`(Player 레이어)가 포함된 경우 카메라가 비정상적으로 가까이 붙는지 테스트해보고, 반드시 `Environment`만 남기고 `Default`는 제외되어 있는지 재확인한다.
8. `Player`의 `_cameraController` 또는 `CameraController`의 `_inputManager`/`_cameraTransform` 필드를 비운 채 Play 하면 예외 없이 아무 반응도 하지 않는지 확인한다(null 체크 동작 확인, 선택 사항).

## 5. 구현 범위 외 사항 (참고)

- LockOn, Q/E 타겟 전환, 마우스 기반 pitch(상하) 카메라 조작은 구현하지 않았다. `Look` 액션은 `PlayerInput.inputactions`에 정의되어 있으나 `InputManager`가 구독하지 않는 상태를 그대로 유지한다.
- 씬 파일(.unity) 및 `ProjectSettings`(레이어 정의) 텍스트 직접 편집은 수행하지 않았다(GUID/fileID 및 레이어 인덱스 손상 위험 때문에 3절의 Editor UI 작업으로 안내).
- Kitchen 벽/가구에 Collider를 추가하는 작업(3-2절 4번)을 완료하기 전까지는 `CameraController`의 SphereCast가 바닥 `Plane`의 `MeshCollider` 외에는 아무것도 감지하지 못하므로, 벽 충돌 회피가 시각적으로 확인되지 않을 수 있다.
- 방향성이 있는 캐릭터 모델(예: 이동 방향을 바라보는 애니메이션)을 도입할 경우, `Player` 루트(또는 별도 모델 자식)를 이동 방향에 맞춰 회전시키는 로직이 추가로 필요할 수 있으나 이번 범위에는 포함하지 않았다.
