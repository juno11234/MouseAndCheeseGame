## 1. 기능 요약

플레이어의 이동 속도를 고정값이 아니라 "배고픔 게이지"에 연동시키는 시스템이다. 배고픔은 시간이 지나면 자동으로 감소하고, `IHungerObj` 인터페이스를 구현한 트리거 오브젝트(장애물/사과/치즈)와 접촉하면 그 오브젝트가 들고 있는 변경량(`Amount`, 부호 포함)만큼 즉시 증감한다. 배고픔 비율(0~1)은 `PlayerStatData`의 매핑 곡선을 통해 이동 속도로 변환되며, 배고픔이 0이 되어도 즉사하지 않고 최저 속도로 계속 이동한다(게임오버 판정은 이번 범위 밖, 고양이 AI 쪽 책임).

- **시간 경과 감소**: `HungerController.Update()`가 매 프레임 `-HungerDecayPerSecond * Time.deltaTime`만큼 `ChangeHunger`를 호출한다.
- **오브젝트 접촉**: `HungerController.OnTriggerEnter`가 `IHungerObj`를 구현한 콜라이더(Is Trigger = true)와 닿으면 `hungerObj.Amount`를 그대로 `ChangeHunger`에 전달한다. 장애물은 음수, 사과는 소량 양수, 치즈는 `MaxHunger`보다 훨씬 큰 양수로 설정해 즉시 풀 회복을 표현한다(코드 분기 없음, clamp로 자연스럽게 처리).
- **속도 매핑**: `HungerController.CurrentMoveSpeed`가 매 호출마다 즉시 `HungerRatio`를 `PlayerStatData.EvaluateMoveSpeed()`로 변환한다(캐싱 없음, `CameraController.ForwardDirection`과 동일한 패턴 — Update 실행 순서에 따른 한 프레임 지연 방지).
- **Player 연동**: `Player.HandleMovement()`가 기존 고정 `_moveSpeed` 대신 `_hungerController.CurrentMoveSpeed`를 사용한다. 점프/중력은 이번 변경의 영향을 받지 않는다.
- **외부 소비 지점**: `HungerController.OnHungerChanged(float hungerRatio)` 통합 이벤트와 `HungerRatio`/`CurrentHunger` 프로퍼티를 UI, 카메라 연출, 고양이 AI 등이 구독/폴링할 수 있다. 음식 종류(사과/치즈) 구분이 필요한 Feature(예: 점수 시스템)는 해당 오브젝트에서 `GetComponent<IHungerObj>().HungerObjType`을 직접 읽어야 한다(이벤트 자체에는 종류 정보 없음).

## 3. Unity Editor에서 사용자가 직접 해야 할 수동 작업

코드만으로는 완결되지 않으며, 아래 작업을 Unity Editor UI에서 직접 수행해야 실제로 동작한다.

1. **HungerController 컴포넌트 부착**
   - `SampleScene.unity`를 열고 `Player` GameObject를 선택한다.
   - `Add Component`로 `HungerController`를 부착한다.

2. **PlayerStatData 에셋 생성 및 연결**
   - Project 창에서 우클릭 → `Create > MouseAndCheese > Player Stat Data`로 임시 데이터 에셋을 1개 생성한다(테스트용 값, 정식 밸런싱은 별도 Feature 담당).
   - 생성한 에셋을 `Player`의 `HungerController` 컴포넌트 `_playerStatData` 필드에 드래그해 연결한다.
   - `_playerStatData`를 연결하지 않으면 `Awake()`에서 `NullReferenceException`이 발생한다(의도된 fail-fast 동작, CLAUDE.md 규칙에 따라 null 체크를 추가하지 않았다).

3. **Player 컴포넌트 필드 연결**
   - `Player` 컴포넌트의 `_hungerController` 필드에 같은 GameObject에 부착한 `HungerController`를 연결한다.
   - `_hungerController`가 비어 있으면 `HandleMovement()` 호출 시 `NullReferenceException`이 발생한다(동일하게 의도된 동작).

4. **(이번 범위 밖, 향후 "음식·장애물 랜덤 생성" Feature 구현 시 필요)**
   - 장애물/사과/치즈 프리팹에 `IHungerObj`를 구현한 컴포넌트를 만들어 부착하고, Collider를 `Is Trigger = true`로 설정해야 `HungerController.OnTriggerEnter`가 반응한다.
   - 해당 컴포넌트는 인스펙터에서 `HungerObjType`과 `Amount`(부호까지 반영된 최종 변경량)를 설정할 수 있어야 한다. 태그는 사용하지 않는다(인터페이스 기반 식별로 전환됨).

## 4. 동작 확인 방법

1. 위 3번까지 수동 작업을 완료한 뒤 Play 모드로 진입한다.
2. 시간이 지남에 따라 `HungerController.CurrentHunger`(Inspector에서 확인 가능하도록 `[SerializeField]`는 아니므로, 필요 시 디버그 로그나 임시 UI로 확인)가 서서히 감소하고, 그에 따라 플레이어 전진 속도가 느려지는지 확인한다.
3. 배고픔이 0에 도달해도 캐릭터가 멈추지 않고 `PlayerStatData._minMoveSpeed`로 계속 이동하는지 확인한다(즉사 없음).
4. `IHungerObj` 구현 프리팹이 아직 없으므로, 장애물/음식 접촉 테스트는 "음식·장애물 랜덤 생성" Feature가 프리팹을 만든 이후에 가능하다. 임시로 테스트하려면 트리거 콜라이더와 `IHungerObj`를 구현한 간단한 테스트 컴포넌트를 만들어 `Amount`를 양수/음수로 설정해 확인할 수 있다.

## 5. 이번 범위에 포함하지 않은 것

- 태그(Tag Manager) 추가: 인터페이스 기반 식별로 전환하면서 불필요해졌다.
- 장애물과의 물리적 충돌(막힘): 장애물은 트리거로만 처리하며, "충돌 1회 = 페널티 1회"를 보장하기 위해 의도적으로 통과 가능하게 설계했다.
- 배고픔 0 도달 시 게임오버 판정: 고양이 AI("플레이어 추격") Feature의 책임이며, 이번 구현은 `HungerRatio`/`OnHungerChanged`를 읽을 수 있는 인터페이스만 제공한다.
- 점프/중력의 배고픔 연동: 이번 Task 범위는 전진 이동 속도로 한정했다.
- `PlayerStatData`의 정식 밸런싱 값: 실제 수치 결정은 "플레이어,고양이 스탯 관련 데이터 테이블" Feature가 담당하며, 이번 클래스는 임시 필드 계약 스텁이다.
