## 1. 기능 요약

풀잎(Leaf)에 접촉하면 플레이어가 일정 시간(제한 시간) 동안 "비행" 상태에 들어가는 시스템이다. 비행 중에는 중력 대신 고정 속도로 자동 상승하며, 좌우/전진 이동은 지상 이동과 동일한 기존 코드 경로(`HandleMovement`/`HandleRotation`, 카메라 회전 기반)를 그대로 재사용한다. 제한 시간이 다 되거나 바닥에 닿으면 즉시 Run 상태로 복귀하며, 착지 지점이 "성공/실패"인지는 이 기능이 직접 판정하지 않는다(보상 판정은 별도 Feature 책임).

별도 컴포넌트(`LeafFlightController`)로 분리했던 이전 설계는 최종적으로 폐기되었고, 비행 상태(Run/Fly)·타이머·이벤트는 전부 `Player.cs` 내부의 `PlayerMoveState` enum과 `SetMoveState()`로 흡수되었다. `Player.Update()`는 `switch(_moveState)`로 기존 `ApplyGravity()`(Run)와 신규 `ApplyFlying()`(Fly)을 분기 호출하며, 기존 `ApplyGravity()`/`HandleMovement()`/`HandleRotation()`/`IsGrounded()`는 전혀 손대지 않았다.

- **비행 시작**: `Player.OnTriggerEnter`가 Run 상태에서 `LeafFlightTrigger`가 붙은 콜라이더(Is Trigger = true)와 접촉하고 그 풀잎이 `IsAvailable`(쿨타임 아님)이면 `StartFlight(leaf)`를 호출한다. `_flightTimeRemaining`을 `LeafFlightData.FlightDuration`으로 초기화하고, 그 풀잎만 `StartCooldown()`으로 쿨타임에 들어가며, `SetMoveState(Fly)`로 전환한다.
- **비행 중**: `Player.Update()`가 매 프레임 `ApplyFlying()`을 호출해 `_velocity.y`를 `LeafFlightData.AscendSpeed`로 고정하고 위로 이동시킨다. `_flightTimeRemaining`이 감소하며 0 이하가 되면 착지 여부와 무관하게 `SetMoveState(Run)`으로 강제 종료한다. 좌우/전진 이동은 기존 `HandleMovement`/`HandleRotation`이 그대로 담당(별도 좌우 조작 로직 없음, `HungerController.CurrentMoveSpeed` 기반 전진 속도 그대로 적용).
- **비행 종료(착지)**: `Update()`가 Fly 상태에서 `IsGrounded()`(기존 SphereCast 재사용, 착지 지점 구분 없음)를 감지하면 `SetMoveState(Run)`으로 되돌린다.
- **쿨타임**: `Player`가 아니라 각 `LeafFlightTrigger`가 개별로 관리한다. `Update()`에서 시간 경과로 `_cooldownTimeRemaining`을 감소시키며, 그라운드 여부와 무관하게 단순 타이머로 충전된다. 풀잎마다 독립적이라 하나를 쓰는 동안에도 다른 풀잎은 이미 사용 가능할 수 있다.
- **외부 소비 지점**: `Player.OnMoveStateChanged(PlayerMoveState newState)` 이벤트(고양이 AI가 Fly/Run 전환 시점에 갭 기록·정지·속도 보정을 트리거하는 훅), `Player.MoveState` 폴링, `Player.FlightTimeRatio`(0~1, 비행 게이지 UI 폴링용, Fly 상태가 아니면 0)를 다른 Feature가 참조할 수 있다.

## 3. Unity Editor에서 사용자가 직접 해야 할 수동 작업

코드만으로는 완결되지 않으며, 아래 작업을 Unity Editor UI에서 직접 수행해야 실제로 동작한다(이번 세션에서는 Unity Editor MCP 도구를 사용할 수 없어 코드만 구현했다).

1. **`LeafFlightData` 에셋 생성**
   - Project 창에서 우클릭 → `Create > MouseAndCheese > Leaf Flight Data`로 임시 데이터 에셋을 1개 생성한다(테스트용 값, 정식 밸런싱은 별도 Feature 담당).

2. **`Player` 컴포넌트 필드 연결**
   - `SampleScene.unity`를 열고 `Player` GameObject를 선택한다.
   - `Player` 컴포넌트의 `_leafFlightData` 필드에 1번에서 만든 에셋을 드래그해 연결한다.
   - 더 이상 별도로 부착할 컴포넌트는 없다(`LeafFlightController`가 `Player.cs`로 흡수되어 애초에 존재하지 않음).
   - `_leafFlightData`를 연결하지 않으면 비행 시작 시 `NullReferenceException`이 발생한다(의도된 fail-fast 동작, CLAUDE.md 규칙에 따라 null 체크를 추가하지 않았다).

3. **`Leaf.prefab`에 Collider + `LeafFlightTrigger` 부착**
   - `Assets/4_Prefabs/Leaf.prefab`을 연다.
   - Collider(예: `SphereCollider`)를 추가하고 `Is Trigger = true`로 설정한다.
   - `LeafFlightTrigger` 컴포넌트를 추가하고, 그 `_leafFlightData` 필드에 1번에서 만든 것과 **같은** `LeafFlightData` 에셋을 연결한다(쿨타임 수치 공유 목적).
   - `_leafFlightData`를 연결하지 않으면 `StartCooldown()` 호출 시 `NullReferenceException`이 발생한다(동일하게 의도된 동작).

4. **(이번 범위 밖, 맵 배치 Feature 구현 시 필요)**
   - 풀잎/싱크대를 맵의 어느 위치에 몇 개 배치할지는 별도 Feature 책임이며, 이번 구현은 풀잎 프리팹이 위 3번 컴포넌트 계약(Collider + `LeafFlightTrigger`)을 만족해야 한다는 요구사항만 남긴다.

## 4. 동작 확인 방법

1. 위 3번까지 수동 작업을 완료한 뒤 Play 모드로 진입한다.
2. 플레이어를 이동시켜 `Leaf.prefab` 인스턴스의 트리거 콜라이더에 접촉시키면, 중력 대신 자동 상승으로 떠오르는지 확인한다(전진/좌우는 기존 카메라 회전 기반 조작 그대로 동작해야 한다).
3. `LeafFlightData.FlightDuration`(기본 5초) 안에 바닥에 닿지 않으면 자동으로 Run 상태로 복귀하며 자유낙하가 시작되는지 확인한다.
4. 비행 중 바닥(레이어 6, `_groundLayer`)에 닿으면 즉시 Run 상태로 복귀하는지 확인한다.
5. 같은 풀잎에 다시 접촉했을 때 `LeafFlightData.CooldownDuration`(기본 15초) 동안 비행이 시작되지 않는지, 그 시간이 지나면 다시 시작되는지 확인한다. 다른 풀잎 인스턴스는 이 쿨타임과 무관하게 즉시 사용 가능해야 한다.
6. 비행 중 스페이스바(점프) 입력이 무시되는지 확인한다(`_velocity`/`_jumpCount` 오염 없음).
7. 고양이 AI가 아직 없으므로 갭 기록/정지/속도 보정 테스트는 불가능하다 — `Player.OnMoveStateChanged`가 정상적으로 Fly/Run 시점에 발생하는지는 임시 로그 구독 등으로 별도 확인해야 한다.

## 5. 확정되지 않아 이번 구현에서 임의로 결정하지 않은 사항 (계획서 0절 그대로 유지)

- **비행 제한 시간 등 구체적 수치**: `LeafFlightData`의 `_flightDuration`(5f)/`_ascendSpeed`(3f)/`_cooldownDuration`(15f)는 개발 테스트용 임시 플레이스홀더 값이다. 정식 밸런싱 수치는 "데이터 테이블" Feature 또는 플레이테스트를 거쳐 별도로 결정해야 한다.
- **비행 중 배고픔(속도) 감소 지속 여부**: `HungerController.Update()`는 이번 구현에서 전혀 건드리지 않았다. 따라서 비행 중에도 배고픔이 계속 감소한다(기존 동작 유지가 기본값). 비행 중 감소를 멈춰야 한다는 결정이 내려지면 `HungerController`에 별도 일시정지 훅을 추가하는 후속 작업이 필요하다.
- **비행 시작 직후 `IsGrounded()`가 곧바로 착지로 오인할 위험**: 풀잎 접촉 시점엔 보통 이미 지상에 있으므로, 비행이 막 시작된 프레임에도 아직 충분히 떠오르기 전이면 `IsGrounded()`가 여전히 `true`를 반환해 비행이 시작하자마자 곧바로 종료될 수 있다. 방지 방법(최소 상승 유예 시간 등)은 정해지지 않아 방어 코드를 추가하지 않았다.

## 6. 이번 범위에 포함하지 않은 것

- 갭(고양이와의 거리) 계산/기록/정지/속도 보정: 전적으로 향후 "고양이 AI" Feature 책임. `Player`는 `OnMoveStateChanged`/`MoveState` 훅만 제공한다.
- 착지 성공/실패 판정, 보상(음식 스폰·점수) 지급: `Player`는 착지 지점을 구분하지 않는다. 보상 여부는 "점수·보상 시스템" Feature가 착지 후 플레이어 위치로 직접 판단해야 한다.
- 비행 게이지/쿨타임 UI: `Player.FlightTimeRatio`만 노출했으며 실제 UI는 만들지 않았다. 쿨타임 UI를 위한 별도 값(`CooldownRatio` 등)도 `LeafFlightTrigger`에 두지 않았다.
- 풀잎/싱크대의 맵 배치 위치·개수: 별도 "맵 배치" Feature 책임.
- `LeafFlightData`의 정식 밸런싱 값: 실제 수치 결정은 "데이터 테이블" Feature 담당이며, 이번 클래스는 임시 필드 계약 스텁이다.
