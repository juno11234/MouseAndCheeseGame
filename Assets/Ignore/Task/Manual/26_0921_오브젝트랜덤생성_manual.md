## 1. 기능 요약

NavMesh가 베이크된 곳에서만 사과·치즈·쥐덫을 랜덤으로 생성하고, 플레이어가 먹으면(닿으면) 오브젝트 풀로 회수하는 스포너다.

- **생성 대상**: `Assets/4_Prefabs/Obj/`의 `Apple_Obj`, `Cheese_Obj`, `Trap_Obj` 세 프리팹. 종류별로 `FoodPool` 하나를 가진다.
- **생성 시점**: `Start`에서 `InitialSpawnAttempts`(임시 5)번 생성을 시도하고, 이후 `SpawnInterval`(임시 1초)마다 한 번 시도한다. "5개 정도"는 시도 5회로 구현했으므로 위치를 못 찾으면 5개보다 적을 수 있다.
- **종류 결정**: 시도마다 사과:치즈:쥐덫 가중치(임시 9:1:2)로 하나를 고른다. 종류별 동시 존재 상한(임시 사과 20, 치즈 2, 쥐덫 6)에 닿으면 그 시도는 건너뛴다.
- **위치 뽑기**: `NavMeshRandomPointSampler`가 시작 시 `NavMesh.CalculateTriangulation()`을 한 번 읽어 삼각형별 가중치 누적 배열을 만들고, 이후에는 이진 탐색 한 번과 `NavMesh.SamplePosition` 한 번으로 NavMesh 위 지점을 뽑는다. NavMesh가 없거나 비면 아무것도 생성하지 않는다.
- **높이 구간**: 삼각형 무게 중심의 월드 Y가 `ElevatedHeight`(임시 1) 이상이면 면적에 `ElevatedWeightMultiplier`(임시 3)를 곱해 가구 위처럼 높은 표면의 생성 확률을 올린다. `RestrictHeight`(기본 꺼짐)를 켜면 `[RestrictedMinHeight, RestrictedMaxHeight]` 구간은 생성하지 않는다. 사과·치즈·쥐덫이 샘플러를 공유하므로 규칙이 세 종류에 똑같이 적용된다.
- **위치 검증**: 배치 좌표(NavMesh 표면 + `SpawnHeightOffset` 0.08)를 기준으로, 플레이어와 `MinDistanceFromPlayer`(6m) 이상, 이미 생성된 모든 오브젝트와 `MinObjectDistance`(4m) 이상 떨어져야 한다. 고양이 위치는 보지 않는다. 위치 탐색은 최대 `MaxPlacementAttempts`(10)번이며 실패하면 그 시도는 포기한다.
- **치즈와 동반 쥐덫**: 치즈를 소환할 때 치즈 위치를 먼저 찾고, 그 주변 링 `[TrapMinDistanceFromCheese 1.5, TrapMaxDistanceFromCheese 3]`m 안에서 동반 쥐덫 위치를 찾는다. 둘 다 찾고 쥐덫 풀에 자리가 있을 때만 함께 생성한다. 쥐덫은 치즈와 무관하게 독립적으로도 계속 생성된다(치즈가 먹히거나 만료돼도 쥐덫은 남는다).
- **치즈 만료**: 치즈만 `CheeseLifetime`(임시 15초) 뒤 풀로 회수된다. 사과와 쥐덫은 만료가 없다.
- **소비와 회수**: `Food.OnTriggerEnter`가 `HungerController`와 닿으면 `ChangeHunger(_amount)`를 적용한 직후 `OnConsumed(this)`를 발생시킨다. 스포너가 이를 구독해 생성 때 기록한 풀(`_activeFoods[food]`)로 반환한다. `Food._type`이 아니라 어느 풀에서 꺼냈는지로 반환 대상을 정하므로 프리팹의 `_type` 설정 실수와 무관하게 풀이 뒤섞이지 않는다. 쥐덫도 밟으면 1회용으로 회수된다.
- **이벤트 `Action` 전환**: `Food.OnConsumed`는 `Action<Food>`이고, 기존 `Player.OnMoveStateChanged`, `CatController.OnGapChanged`/`OnPlayerCaught`, `InputManager.OnAutoInput`/`OnJumpInput`, `HungerController.OnHungerChanged`의 커스텀 델리게이트 선언을 삭제하고 `Action` 계열로 바꿨다. 이벤트 이름, `?.Invoke(...)` 호출부, 구독 코드, 핸들러 시그니처는 변경이 없다.

## 3. Unity Editor에서 사용자가 직접 해야 할 수동 작업

코드만으로는 스포너가 동작하지 않는다. 아래를 Unity Editor에서 수행해야 한다(코드 구현 범위 밖이라 직접 하지 않았다).

1. **`Apple_Obj.prefab`에 `Food` 부착 (프리팹 편집 모드)**: `Assets/4_Prefabs/Obj/Apple_Obj.prefab`을 열어 루트에 `Food` 컴포넌트를 추가한다. **`_type`을 Apple로 바꾼다**(기본값이 Obstacle). `_amount`는 임시로 20을 넣는다. 콜라이더는 이미 Is Trigger ON이다. 스포너는 `_type`에 의존하지 않지만, 점수 등 다른 Feature를 위해 맞춰 둔다.
2. **`ObjectSpawnData` 에셋 생성**: `Assets/5_Data/`에서 우클릭 -> Create -> MouseAndCheese -> Object Spawn Data. 기본값 그대로 임시로 쓴다. `Restrict Height`는 꺼져 있고 `Elevated Height`/`Elevated Weight Multiplier`(1, 3)만 켜져 있다.
3. **씬에 `ObjectSpawner` 추가**: `SampleScene.unity`에 빈 GameObject `ObjectSpawner`를 만든다. **위치 (0,0,0), 회전 (0,0,0), 스케일 (1,1,1)**로 둔다(풀 인스턴스가 이 오브젝트의 자식이 되므로 스케일이 1이 아니면 오브젝트 크기가 왜곡된다). `ObjectSpawner` 컴포넌트를 추가하고 다음을 연결한다.
   - `_player`: 씬의 `Player` 오브젝트
   - `_spawnData`: 2번에서 만든 에셋
   - `_applePrefab`/`_cheesePrefab`/`_trapPrefab`: `Assets/4_Prefabs/Obj/`의 `Apple_Obj`, `Cheese_Obj`, `Trap_Obj` (**씬에 놓인 인스턴스가 아니라 프로젝트 창의 프리팹 에셋**)
   - `_agentTypeId`: 0(Humanoid), `_areaMask`: -1(모든 Area, 기본값)
4. **씬의 수동 배치 오브젝트 처리(사용자 결정)**: 씬에 이미 놓인 `Cheese_Obj (1)`, `Cheese_Obj`, `Trap_Obj`는 풀과 무관하게 남고 구독자가 없어 지금 동작(닿을 때마다 반복 적용)이 유지된다. 지울지 남길지는 사용자가 정한다. 스포너는 자신이 만든 것만 추적하므로 남아 있어도 최소 간격 검사에는 들지 않는다(같은 자리에 스폰돼 겹칠 수 있다는 점만 유의).
5. **NavMesh 베이크 확인**: `Kitchen`의 `NavMeshSurface`에 베이크 데이터(`NavMesh-Kitchen.asset`)가 연결돼 있는지 본다. 재베이크는 필요 없다.
6. **Console 컴파일 오류 확인**: 5절의 [검증 필요] API 목록을 함께 본다.
7. (선택) 씬 뷰에서 Navigation 표시를 켜고 가구 위 NavMesh의 Y를 확인한 뒤 `ObjectSpawnData`의 `Elevated Height`를 조정한다. 생성을 제한할 높이 구간이 있으면 `Restrict Height`를 켜고 최소·최대를 입력한다.

## 4. 동작 확인 방법 (Play 모드, 사용자가 직접 확인)

계획서 4-7절의 시나리오 1~21이 검증 기준이다. 핵심만 추린다.

1. **시작 직후**: `ObjectSpawner` 아래에 비활성 자식이 사과 20, 치즈 2, 쥐덫 6으로 28개 만들어지고, 그중 시작 시도 5회 결과만큼(최대 5개)이 활성이다. 활성 오브젝트가 전부 NavMesh 위에 있는지 씬 뷰에서 확인한다.
2. **간격과 분포**: 임의 두 오브젝트 거리 4m 이상(치즈-동반 쥐덫 쌍은 1.5~3m), 플레이어 6m 안에는 생성되지 않는다. 벽·가구 가장자리에 붙지 않는다.
3. **높이 규칙**: 가구 위 표면이 있다면 지상보다 높은 밀도로 생성된다. 배율을 1로 내리면 면적 비례로 돌아간다.
4. **소비와 회수**: 사과를 먹으면 배고픔이 20 오르고 사라진다. 자식 수는 28개로 유지되고 새 `Instantiate`가 없다. 쥐덫은 -10 후 사라지고 치즈는 최대까지 채운 뒤 치즈만 사라진다(동반 쥐덫은 남는다).
5. **치즈 만료**: 먹지 않고 15초가 지나면 치즈만 회수되고 쥐덫은 남는다.
6. **트리거 인식(Y 교훈)**: 바닥과 가구 위에서 반복적으로 지나가 먹히는지 본다. 안 먹히면 `SpawnHeightOffset`을 0.05 단위로 조정한다. 값이 크면 쥐덫을 점프로 넘기 어려워진다.
7. **이중 반환 예외 없음**: `Trying to release an object that has already been released to the pool` 예외가 뜨지 않는다.
8. **`Action` 전환 회귀**: 점프·자동 전진 입력, 배고픔 게이지 UI 갱신, 풀잎 비행 시 고양이 정지·복원과 경로 기록, 갭·포획 이벤트가 전환 전과 똑같이 동작한다.
9. **쥐덫 포화 시 치즈(관찰 항목)**: 쥐덫이 상한(6)까지 차면 동반 쥐덫 자리가 없어 치즈가 생성되지 않을 수 있다. 얼마나 오래 가는지, 쥐덫을 밟아 자리가 나면 다시 생기는지 본다.

## 5. 검증하지 못한 부분과 [검증 필요] API

- **Unity 컴파일을 하지 못했다.** 아래는 계획서가 [검증 필요]로 표시한 API이며 Console에서 오류로 드러날 수 있다. 이름이 다르면 그에 맞춰 수정한다.
  - `ObjectPool<T>` 생성자 인자 이름(`createFunc`, `actionOnRelease`, `actionOnDestroy`, `collectionCheck`, `defaultCapacity`, `maxSize`)과 `CountActive` 프로퍼티 (`FoodPool.cs`)
  - `NavMesh.CalculateTriangulation()`의 `areas` 배열이 삼각형당 Area 인덱스 하나인지, 그리고 6000.3.19f1에서 사용 가능한지 (`NavMeshRandomPointSampler.cs` 생성자)
  - `NavMeshQueryFilter`의 `agentTypeID`/`areaMask` 동작, `NavMesh.SamplePosition(..., NavMeshQueryFilter)` 오버로드
  - 삼각형 높이와 `SamplePosition` 결과 높이의 차이, 가구 위 NavMesh 표면의 실제 높이·면적(베이크 데이터가 바이너리라 읽지 못함)
  - `Start` 시점에 `NavMeshSurface` 데이터가 이미 등록돼 있는지(실행 순서 가정)
- **Play 검증을 하지 못했다.** 트리거 인식 여부, 소비·회수 흐름, 밸런스 체감은 모두 사용자가 확인해야 한다.
- **정적 확인만 수행**: 델리게이트 타입 이름 5개(`MoveStateChangedHandler`, `GapChangedHandler`, `PlayerCaughtHandler`, `InputButtonHandler`, `HungerChangedHandler`)와 `delegate` 키워드가 `Assets/02_Scripts` 어디에도 남지 않았음을 Grep으로 확인했다. 구독 핸들러(`ToggleAutoMove(bool)`, `HandleJumpInput(bool)`, `HandleMoveStateChanged(PlayerMoveState)`, `HandlePlayerMoveStateChanged(PlayerMoveState)`, `HandleHungerChanged(float)`)의 시그니처가 `Action<T>`와 호환됨을 확인했다. `using System;`을 추가한 5개 파일에는 `Random.`/`Object.` 사용이 없다(신규 스폰 파일에만 있고 그쪽에는 `using System;`을 넣지 않았다).

## 6. 확정되지 않아 임의로 결정하지 않은 사항 (계획서 0절 그대로 유지)

- **수치 전부**: 상한 20/2/6, 가중치 9:1:2, 주기 1초, 최소 간격 4m·6m, 치즈 수명 15초, 쥐덫 링 1.5~3m, `SpawnHeightOffset` 0.08은 자리 표시자다. `ObjectSpawnData` 한 곳에서 바꾼다.
- **높이 구간**: `ElevatedHeight` 1, 배율 3은 추정값이고, `RestrictHeight`는 값이 정해지기 전에 생성을 막지 않도록 기본 꺼짐이다. 제한 구간이 "구간"인지 "상한"인지는 미확정(상한이면 최대값을 크게 잡으면 같은 표현).
- **쥐덫 굶주림 위험**: 쥐덫에 수명이 없어 밟히기 전까지 풀 상한을 차지하고, 상한까지 차면 치즈(동반 쥐덫 필요)가 생성되지 않을 수 있다. 코드로 막지 않았다.
- **회수 범위**: 사과 만료, 플레이어 뒤로 멀어진 오브젝트 회수는 넣지 않았다.
- **도달 가능성 필터**: 고양이·플레이어 도달 가능성은 확인하지 않는다. 링크로 이어지지 않은 가구 위 NavMesh나 고립 섬이 후보에 들 수 있다.
- **캐시 한계**: 샘플러는 시작 시 1회 캐시라 런타임 재베이크에는 낡는다. `OnDestroy`에서 풀을 `Clear()`하지 않는다(리스타트 Feature에서 정리).
- **문서 부채**: `HungerController` 클래스 summary의 `IHungerObj` 서술이 실제와 어긋나 있으나(리뷰 B9 유형) 이번 범위 밖이라 그대로 뒀다.

## 7. 계획서와 달랐던 점

- 기존 5개 파일의 "변경 전" 코드는 계획서와 실제 파일이 일치했다. 줄 번호만 작성 시점과 조금 달랐고 현재 파일에서 다시 찾아 적용했다.
- `Food.cs`는 기존 스타일(`if(` 공백 없음)을 유지했다(계획서 6-19절 그대로).
- `Player.cs`는 델리게이트 선언을 삭제하고 남는 연속 빈 줄 2개를 정리해 `Fly` 해시 필드와 `[SerializeField]` 사이 빈 줄 1개로 맞췄다(계획서에 없는 공백 정리, 코드 변경 아님).
- 그 외 계획서 스니펫은 로직·수치·주석 모두 그대로 구현했다.

## 8. 롤백 방법

`Assets/02_Scripts/Spawn/` 폴더를 삭제하고, git으로 `Food.cs`, `Player.cs`, `CatController.cs`, `InputManager.cs`, `HungerController.cs`를 되돌린다. 단, `Player.cs`, `Food.cs`, `CatController.cs`, `HungerController.cs`에는 이번 작업 이전의 사용자 미커밋 수정이 있었으므로 전체 `git checkout`은 그 수정까지 지운다. 이번 변경분(`using System;`, 델리게이트 선언, 이벤트 타입, `Food.OnConsumed`)만 수동으로 되돌리는 것이 안전하다. 에디터 작업(`ObjectSpawnData.asset`, `Apple_Obj.prefab`의 `Food`, 씬의 `ObjectSpawner`)을 했다면 함께 되돌린다.
