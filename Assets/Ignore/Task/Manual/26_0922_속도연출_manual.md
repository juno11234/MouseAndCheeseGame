- 작성 날짜: 2026-09-22 (26_0922)
- 작성자: builder (Claude Code)
- 참고 계획 파일: `Assets/Ignore/Task/Plan/26_0922_속도연출_plan.md` (계획 그대로 구현, 미확정 수치는 인스펙터 조정 가능한 필드 + 합리적 기본값으로 남김)

## 1. 기능 요약

플레이어의 이동 속도(`HungerController.CurrentMoveSpeed`, 배고픔 비율로부터 계산됨)가 임계값 이상이면 카메라 시야각(FOV)을 서서히 넓히고, 화면에 방사형(radial) 블러를 서서히 적용해 속도감을 연출하는 기능이다. 고양이와의 갭(`CatController.Gap`)은 전혀 참조하지 않는다.

- **트리거 판정**: `SpeedEffectController.IsSpeedBoosted()`가 `SpeedEffectData.HungerRatioThreshold`(기본 0.75)를 `PlayerStatData.EvaluateMoveSpeed()`로 속도 단위로 환산한 뒤, `HungerController.CurrentMoveSpeed`와 비교한다. 매 프레임 폴링 방식이며 캐싱하지 않는다(`GapDistanceUI`와 동일한 패턴).
- **카메라 FOV(관성)**: `LateUpdate()`에서 목표 FOV(발동 시 `BoostedFov`, 평상시 `BaseFov`)로 `Mathf.SmoothDamp`를 사용해 서서히 근접시킨다. 즉시 스냅되지 않고 부드럽게 전환되는 것 자체를 "관성"으로 채택했다(카메라 위치/회전 랙은 포함하지 않음, 계획 0-2절 근거).
- **화면 라디얼 블러**: 같은 방식으로 블러 강도(0~`MaxBlurIntensity`)를 `SmoothDamp`로 근접시켜 `SpeedRadialBlur_Mat.mat`의 `_BlurIntensity`에 매 프레임 반영한다. 실제 블러는 `SpeedRadialBlur.shader`가 `PC_Renderer.asset`의 두 번째 `FullScreenPassRendererFeature`(툰 외곽선 다음 순서)를 통해 화면 전체에 적용한다.
- **기존 파일 미수정**: `CameraController.cs`, `HungerController.cs`, `PlayerStatData.cs`, `CatController.cs`는 전혀 수정하지 않았다. `SpeedEffectController`는 `CameraPivot`의 형제 컴포넌트로만 추가되어 `Camera.fieldOfView`만 별도로 건드린다.

## 3. 기본값(인스펙터에서 조정 가능)

계획서 "0. 미확정 사항"에 따라 정식 수치가 확정되지 않아, 아래는 모두 `SpeedEffectData` 인스펙터에서 자유롭게 조정 가능한 임시 기본값이다(정식 밸런싱은 "데이터 테이블" Feature 책임).

| 필드 | 기본값 | 설명 |
|---|---|---|
| `_hungerRatioThreshold` | 0.75 | 연출이 발동하는 배고픔 비율 임계값(0~1) |
| `_baseFov` | 60 | 평상시 카메라 시야각(기존 `Main Camera`의 `field of view: 60`과 동일하게 맞춤) |
| `_boostedFov` | 75 | 연출 발동 시 목표 시야각 |
| `_fovSmoothTime` | 0.5 | FOV가 목표값에 도달하는 대략적인 시간(`SmoothDamp`의 `smoothTime`) |
| `_maxBlurIntensity` | 0.3 | 연출 발동 시 라디얼 블러의 최대 강도(0~1) |
| `_blurSmoothTime` | 0.5 | 블러 강도가 목표값에 도달하는 대략적인 시간 |

셰이더 내부 `SAMPLE_COUNT`(8)는 컴파일 타임 `#define` 상수로, 런타임 조정 대상이 아니다(계획 0-5절, 6-6절 근거).

## 4. Unity Editor에서 사용자가 직접 확인해야 할 사항

이번 구현은 GUID·YAML을 포함한 모든 파일(스크립트, 셰이더, 머티리얼, 데이터 에셋, `PC_Renderer.asset`, `Player.prefab`)을 텍스트로 직접 작성했다(Unity Editor 미실행 환경). Unity Editor로 처음 열 때 아래 사항을 반드시 확인해야 한다.

1. **Unity Editor에서 프로젝트를 열어 콘솔에 에러/경고가 없는지 확인**한다. 특히 `SpeedRadialBlur.shader` 컴파일 성공 여부, `PC_Renderer.asset`의 두 번째 `FullScreenPassRendererFeature`가 인스펙터에 정상적으로 표시되는지(내부 `m_RendererFeatureMap` 캐시는 에디터가 파일을 열 때 자동 재계산되는 필드로, 수동 작성 시 갱신하지 않았다).
2. **`Player.prefab`의 `CameraPivot` 오브젝트**를 선택해 `SpeedEffectController` 컴포넌트의 5개 필드(`_hungerController`, `_playerStatData`, `_speedEffectData`, `_camera`, `_radialBlurMaterial`)가 모두 연결되어 있는지 확인한다. 비어 있으면 Play 모드에서 즉시 `NullReferenceException`이 발생한다(의도된 fail-fast, CLAUDE.md 규칙에 따라 null 체크를 추가하지 않음).
3. **`PC_Renderer.asset`의 Renderer Feature 순서**가 `ScreenSpaceAmbientOcclusion` → 툰 외곽선(`FullScreenPassRendererFeature`) → 라디얼 블러(`FullScreenPassRendererFeature`) 순서인지 확인한다(같은 `injectionPoint`를 공유하는 여러 Renderer Feature는 목록 순서대로 실행되므로, 라디얼 블러가 외곽선 이후에 합성되어야 한다).
4. Play 모드로 진입해 배고픔 게이지가 임계값(기본 75%) 이상으로 차오를 때 카메라 FOV가 서서히 넓어지고 화면 가장자리가 서서히 방사형으로 흐려지는지, 임계값 아래로 내려가면 서서히 원상 복귀하는지 육안으로 확인한다.

## 5. 이번 범위에 포함하지 않은 것

- **카메라 위치/회전 랙(포지션 랙, 스웨이/틸트)**: "카메라 관성"을 FOV의 부드러운 전환으로만 해석했다(계획 0-2절 해석 A). `CameraController.FollowPlayer()`/`HandleCollision()`과 같은 Transform을 두고 경쟁할 위험이 있어 제외했으며, 필요 시 별도 사양 확정 후 재논의해야 한다.
- **히스테리시스(발동/해제 서로 다른 임계값)**: 단일 임계값 + `SmoothDamp` 완충만 적용했다. 임계값 근처에서의 진동(hunting) 방지 설계는 포함하지 않았다.
- **라디얼 블러 셰이더의 정식 시각적 검증**: 샘플 수(8) 등은 임시값이며, 실제 화면에서 시각적으로 검증되지 않았다(위 4번 항목에서 육안 확인 필요).
- **`Mobile_Renderer.asset` 적용**: 툰 셰이더 Feature 선례를 따라 `PC_Renderer.asset`에만 적용했다.
- **URP 내장 `MotionBlur` 재사용**: `SampleSceneProfile.asset`의 비활성 `MotionBlur`는 그대로 두고 별도 커스텀 셰이더로 구현했다(계획 0-7절 근거).
- **`SpeedEffectData`의 정식 밸런싱 값**: 실제 수치 결정은 "데이터 테이블" Feature가 담당하며, 이번 클래스는 임시 필드 계약 스텁이다.
