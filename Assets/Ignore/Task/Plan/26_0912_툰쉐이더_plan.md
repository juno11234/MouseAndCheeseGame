# 툰 셰이더(Cel-Shading, HLSL) 구현 계획

- 작성 날짜: 2026-09-12 (26_0912)
- 작성자: planner (Claude Code)
- 배경: 쥐(Rat)/고양이(Cat) 캐릭터를 Blender에서 임포트했고, 현재는 URP 기본 Lit 셰이더(PBR)를 사용 중이다. "쥐와 치즈"는 캐주얼 모바일 러너 게임이므로 사실적인 PBR보다 가독성이 높고 스타일이 통일된 카툰(Cel-shading) 룩이 적합하다고 판단해, HLSL 기반 커스텀 URP 셰이더를 새로 작성하려 한다.
- 요청 범위: HLSL로 툰 셰이더를 직접 작성하고, 쥐/고양이 캐릭터 머티리얼(`Rat_Mat`/`Cat_Mat`)뿐 아니라 부엌 환경 머티리얼(`Oven_Mat`/`Sink_Mat`/`Table&Chair_Mat`/`Wall_Mat`/`refrigerator_Mat`)까지 총 7개 머티리얼에 적용 가능한 형태로 구현한다. 렌더러 범위는 PC(`PC_Renderer.asset`) 환경으로 한정하고, Mobile 렌더러 호환은 이번 범위에서 제외한다.

## 1. 코드베이스 재조사 결과

### 1-1. 렌더 파이프라인/렌더러 설정 (PC 환경 한정)
- Unity 6000.3.19f1, URP 사용. `Assets/Settings/PC_RPAsset.asset`(기본으로 추정)과 `Mobile_RPAsset.asset` 2개의 파이프라인 에셋, 그리고 각각에 대응하는 `PC_Renderer.asset`/`Mobile_Renderer.asset` 2개의 Universal Renderer Data가 존재한다.
- 이번 작업 범위는 **`PC_Renderer.asset` 기준으로 한정**한다(사용자 확인). `Mobile_Renderer.asset`/`Mobile_RPAsset.asset`과의 호환 여부는 이번 계획에서 다루지 않으며, 추후 모바일 대응이 필요해지면 별도로 재검토한다.
- `PC_Renderer.asset`: `m_RenderingMode: 2`(Forward+), Renderer Feature로 **ScreenSpaceAmbientOcclusion(SSAO)**가 등록되어 있다. SSAO는 `DepthNormals` 패스(노멀 버퍼)를 필요로 하므로, 커스텀 셰이더에도 `DepthNormals` 패스를 넣어야 캐릭터/환경 오브젝트가 SSAO에서 정상 취급된다. (PC 한정이어도 이 Pass 자체는 여전히 필요하다.)

## 5. URP 커스텀 HLSL 셰이더 표준 구조 설명

URP에서 커스텀 라이팅 셰이더를 작성하는 표준 방식은 Shader Graph를 쓰지 않는 한 URP의 `Lit.shader`/`SimpleLit.shader`가 따르는 패턴, 즉 **"얇은 `.shader`(ShaderLab) + 여러 개의 `.hlsl`(실제 로직)" 분리 구조**다. 이번 계획도 이 패턴을 그대로 따른다(1-3절에서 확인했듯 이 프로젝트는 아직 이 패턴을 쓰는 셰이더가 없으므로 URP 표준을 새로 도입하는 것).

- `.shader` 파일: `Properties` 블록(인스펙터 노출용), `SubShader { Tags { "RenderPipeline"="UniversalPipeline" ... } }`, 그리고 Pass별로 `HLSLPROGRAM ... ENDHLSL` 안에서 `#pragma vertex`/`#pragma fragment`로 진입 함수를 지정하고 `.hlsl` 파일을 `#include`한다. **HLSLINCLUDE 블록으로 모든 Pass 공통 include를 SubShader 상단에 한 번에 몰아넣는 방법도 있으나, 이번엔 URP Lit처럼 각 Pass가 필요한 `.hlsl`만 개별 include하는 방식을 택해 불필요한 컴파일 의존성을 줄인다.**
- Forward+/Forward 렌더링 모두에서 동작하려면 `ForwardLit` Pass의 `Tags { "LightMode" = "UniversalForward" }`가 필수이며, 그림자를 드리우려면 `ShadowCaster` Pass, SSAO/기타 렌더러 피처 호환을 위해 `DepthOnly`/`DepthNormals` Pass가 필요하다(1-1절 근거).
- URP Lit/SimpleLit 셰이더 원본 `.hlsl`을 그대로 include하는 방식(`UsePass` 포함)은 URP 버전마다 내부 구조체/매크로 이름이 바뀔 수 있고 SRP Batcher 호환성 이슈가 보고된 바 있어(URP 공식 문서에서도 `UsePass` 비권장), **이번 셰이더는 필요한 최소 HLSL 코드를 직접 작성**하는 방식을 택했다(URP 코어 라이브러리인 `Core.hlsl`/`Lighting.hlsl`/`Shadows.hlsl`의 공개 유틸 함수만 재사용).

### 5-1. 포스트프로세스(화면공간) 패턴 — 외곽선용 (신규, 6절 근거)

외곽선은 위의 "머티리얼별 `.shader`" 패턴이 아니라 **씬 전체에 한 번 적용되는 포스트프로세스** 패턴을 쓴다. 설치된 URP 패키지(`com.unity.render-pipelines.universal@17.3.0`, `Library/PackageCache`에서 직접 확인)에 이 용도의 **내장 컴포넌트 `FullScreenPassRendererFeature`**가 포함되어 있어(`Runtime/RendererFeatures/FullScreenPassRendererFeature.cs`), 별도의 `ScriptableRendererFeature`/`ScriptableRenderPass` C# 코드를 새로 작성할 필요가 없다.

- 사용법: `PC_Renderer.asset` Inspector에서 **Add Renderer Feature → Full Screen Pass Renderer Feature** 선택 → `requirements`에 `Depth`, `Normal` 체크 → `passMaterial`에 `ToonOutlineFullScreen.shader`를 사용하는 머티리얼(`ToonOutline_Mat.mat`) 연결.
- 이 Renderer Feature는 매 프레임 카메라가 렌더링을 마친 뒤(`injectionPoint` 기본값 `AfterRenderingPostProcessing` 또는 필요시 `BeforeRenderingPostProcessing`) 화면 전체에 걸쳐 `passMaterial`의 셰이더를 한 번 실행하며, 내부적으로 URP의 RenderGraph API(`RecordRenderGraph`)를 사용해 `_BlitTexture`(현재까지 렌더링된 화면 색상), `_CameraDepthTexture`, `_CameraNormalsTexture`를 셰이더에 공급한다(코드에서 직접 확인, `ExecuteMainPass`/`AddFullscreenRenderPassInputPass` 참고).
- 셰이더 쪽에서는 URP 코어의 `Blit.hlsl`(`Packages/com.unity.render-pipelines.core/Runtime/Utilities/Blit.hlsl`)이 제공하는 `Vert(Attributes)` 버텍스 함수와 `Varyings{positionCS, texcoord}` 구조체, `_BlitTexture`를 그대로 재사용하고, 깊이/노멀 샘플링은 `DeclareDepthTexture.hlsl`/`DeclareNormalsTexture.hlsl`이 제공하는 `SampleSceneDepth(uv)`/`SampleSceneNormals(uv)` 헬퍼 함수를 사용한다(7-4절 코드 참고). 이 함수들은 모두 실제 설치된 패키지 파일에서 시그니처를 확인했다.
- 이 방식의 핵심 장점(6절 근거): 새 오브젝트가 씬에 추가돼도, 그 오브젝트가 `DepthNormals` Pass를 가진 셰이더(`Custom/ToonLit` 계열)를 쓰기만 하면 **별도 설정 없이 자동으로 외곽선 대상에 포함**된다. 머티리얼마다 `Outline` Pass를 넣어야 했던 이전 Inverted Hull 방식과 달리, 외곽선 로직 자체는 `ToonOutlineFullScreen.shader` 한 곳에서만 관리하면 된다.

## 6. 툰 셰이딩 핵심 요소 범위 결정

프로젝트 특성(저해상도 스타일라이즈드 캐릭터 2종 + 부엌 환경 오브젝트 5종, 캐주얼 러너 게임, PC 환경 우선, **이후 오브젝트가 계속 추가될 예정**)을 고려해 아래와 같이 범위를 정했다.

| 요소 | 채택 여부 | 방식 | 근거 |
|---|---|---|---|
| N-step 라이팅 밴딩 | 채택 | `smoothstep`으로 2단계(밝음/그림자) 양자화, threshold/smoothness를 머티리얼 프로퍼티로 노출 | 툰 셰이딩의 핵심 요소. 2단계만으로도 카툰 룩 전달에 충분하고, 3단계 이상은 저해상도 캐릭터에서 오히려 밴드 경계가 과하게 눈에 띌 수 있어 제외(필요 시 추후 threshold 배열로 확장 가능하도록 구조화). |
| 림 라이트 | 채택 | 시야 방향 기준 `1 - NdotV`를 임계값 처리 후 가산 | 러너 게임에서 캐릭터가 배경(부엌 가구)과 겹칠 때 실루엣을 부각시켜 가독성을 높이는 데 유용하고, 계산 비용이 낮다. |
| 외곽선 | **채택 변경(2026-09-12): 화면공간 Depth/Normal Edge Detection(Renderer Feature)** | URP 내장 **`FullScreenPassRendererFeature`**(코드 작성 불필요, `PC_Renderer.asset`에 Inspector로 추가)를 사용. Depth+Normal 버퍼를 입력으로 받아, 새로 작성하는 포스트프로세스 셰이더(`ToonOutlineFullScreen.shader`)에서 Roberts Cross 방식으로 인접 픽셀 간 깊이/노멀 차이를 검출해 외곽선을 합성한다 | 두 방식을 비교했다: (A) Inverted Hull(버텍스 노멀 확장, 머티리얼별 Pass) — 머티리얼 단위로 적용해야 해서, **오브젝트가 계속 추가될 예정**이라면 새 오브젝트마다 매번 셰이더를 교체해야 하는 번거로움이 있다. (B) 화면공간 Depth/Normal Edge Detection(Renderer Feature) — `PC_Renderer.asset`에 DepthNormals 버퍼(이미 7절에서 `ToonLit.shader`에 포함하기로 한 Pass)를 사용하는 포스트프로세스 하나만 등록하면, **씬에 새로 추가되는 오브젝트도 별도 설정 없이 자동으로 외곽선 대상에 포함**된다(단, DepthNormals Pass를 가진 셰이더를 쓰는 오브젝트여야 하므로, 새 오브젝트도 `Custom/ToonLit` 계열 셰이더를 쓰는 것이 전제). 사용자가 "이후 오브젝트를 더 추가할 예정이므로 씬 전체에 적용되는 방식"을 명시적으로 요청해 **(B)로 채택을 변경**했다. URP가 `FullScreenPassRendererFeature`를 기본 제공해 C# 코드 작성이 필요 없다는 점도 확인했다(7-4절 근거). |
| Specular Highlight | 미채택 | - | 캐릭터가 저해상도 스타일이라 하이라이트 반사보다 평면적인 셀 컬러가 스타일에 더 부합. 범위 밖으로 명시적 제외. |
| Additional Lights(포인트/스팟) | 미채택 | - | 현재 씬에는 Directional Light(메인 라이트) 하나만 확인됨. 추가 라이트가 생기면 `AdditionalLights` 루프를 추가하는 확장 작업이 별도로 필요하다. |

### 7-1. `ToonLit.shader`

```hlsl
Shader "Custom/ToonLit"
{
    Properties
    {
        _BaseMap("Base Map", 2D) = "white" {}
        _BaseColor("Base Color", Color) = (1, 1, 1, 1)

        [Header(Cel Shading)]
        _ShadowColor("Shadow Color", Color) = (0.6, 0.6, 0.7, 1)
        _ShadowThreshold("Shadow Threshold", Range(0, 1)) = 0.5
        _ShadowSmoothness("Shadow Band Smoothness", Range(0.001, 0.3)) = 0.05

        [Header(Rim Light)]
        _RimColor("Rim Color", Color) = (1, 1, 1, 1)
        _RimThreshold("Rim Threshold", Range(0, 1)) = 0.7
        _RimSmoothness("Rim Smoothness", Range(0.001, 0.3)) = 0.1

        // 외곽선 프로퍼티는 여기 없음 — 화면공간 포스트프로세스(ToonOutlineFullScreen.shader)로 분리됨(6절/7-4절 근거)
    }

    SubShader
    {
        Tags { "RenderType" = "Opaque" "RenderPipeline" = "UniversalPipeline" "Queue" = "Geometry" }

        // 캐릭터 본체를 그리는 메인 라이팅 Pass
        Pass
        {
            Name "ForwardLit"
            Tags { "LightMode" = "UniversalForward" }
            Cull Back

            HLSLPROGRAM
            #pragma vertex ToonVertex
            #pragma fragment ToonFragment

            #pragma multi_compile _ _MAIN_LIGHT_SHADOWS
            #pragma multi_compile _ _MAIN_LIGHT_SHADOWS_CASCADE
            #pragma multi_compile _ _MAIN_LIGHT_SHADOWS_SCREEN
            #pragma multi_compile_fragment _ _SHADOWS_SOFT

            #include "ToonLitInput.hlsl"
            #include "ToonLitForwardPass.hlsl"
            ENDHLSL
        }

        Pass
        {
            Name "ShadowCaster"
            Tags { "LightMode" = "ShadowCaster" }
            Cull Back
            ZWrite On
            ZTest LEqual

            HLSLPROGRAM
            #pragma vertex ToonShadowVertex
            #pragma fragment ToonShadowFragment

            #include "ToonLitInput.hlsl"
            #include "ToonShadowCasterPass.hlsl"
            ENDHLSL
        }

        Pass
        {
            Name "DepthOnly"
            Tags { "LightMode" = "DepthOnly" }
            ColorMask 0
            ZWrite On

            HLSLPROGRAM
            #pragma vertex ToonDepthOnlyVertex
            #pragma fragment ToonDepthOnlyFragment

            #include "ToonLitInput.hlsl"
            #include "ToonDepthOnlyPass.hlsl"
            ENDHLSL
        }

        // PC_Renderer의 SSAO Renderer Feature가 참조하는 노멀 버퍼 생성용 Pass
        Pass
        {
            Name "DepthNormals"
            Tags { "LightMode" = "DepthNormals" }
            ZWrite On

            HLSLPROGRAM
            #pragma vertex ToonDepthNormalsVertex
            #pragma fragment ToonDepthNormalsFragment

            #include "ToonLitInput.hlsl"
            #include "ToonDepthNormalsPass.hlsl"
            ENDHLSL
        }
    }
}
```

### 7-2. `ToonLitInput.hlsl` — 공용 프로퍼티/구조체

```hlsl
#ifndef TOON_LIT_INPUT_INCLUDED
#define TOON_LIT_INPUT_INCLUDED

#include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"
#include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Lighting.hlsl"

TEXTURE2D(_BaseMap);
SAMPLER(sampler_BaseMap);

// SRP Batcher 호환을 위해 머티리얼별 프로퍼티는 반드시 이 CBUFFER 안에 선언한다
CBUFFER_START(UnityPerMaterial)
    float4 _BaseMap_ST;
    half4 _BaseColor;
    half4 _ShadowColor;
    half _ShadowThreshold;
    half _ShadowSmoothness;
    half4 _RimColor;
    half _RimThreshold;
    half _RimSmoothness;
CBUFFER_END

// ForwardLit/ShadowCaster/DepthOnly/DepthNormals Pass가 공유하는 정점 입력
struct Attributes
{
    float4 positionOS : POSITION;
    float3 normalOS   : NORMAL;
    float2 uv         : TEXCOORD0;
};

// ForwardLit Pass의 보간 출력
struct Varyings
{
    float4 positionHCS : SV_POSITION;
    float2 uv          : TEXCOORD0;
    float3 normalWS    : TEXCOORD1;
    float3 positionWS  : TEXCOORD2;
    float4 shadowCoord  : TEXCOORD3;
};

#endif
```

### 7-3. `ToonLitForwardPass.hlsl` — 메인 라이팅(N-step 밴딩 + 림 라이트)

```hlsl
#ifndef TOON_LIT_FORWARD_PASS_INCLUDED
#define TOON_LIT_FORWARD_PASS_INCLUDED

Varyings ToonVertex(Attributes input)
{
    Varyings output = (Varyings)0;

    VertexPositionInputs positionInputs = GetVertexPositionInputs(input.positionOS.xyz);
    VertexNormalInputs normalInputs = GetVertexNormalInputs(input.normalOS);

    output.positionWS = positionInputs.positionWS;
    output.positionHCS = positionInputs.positionCS;
    output.normalWS = normalInputs.normalWS;
    output.uv = TRANSFORM_TEX(input.uv, _BaseMap);

    // 메인 라이트 그림자 샘플링을 위한 그림자맵 좌표. GetMainLight(shadowCoord) 호출에 사용한다
    output.shadowCoord = TransformWorldToShadowCoord(positionInputs.positionWS);

    return output;
}

half4 ToonFragment(Varyings input) : SV_TARGET
{
    half4 baseColor = SAMPLE_TEXTURE2D(_BaseMap, sampler_BaseMap, input.uv) * _BaseColor;

    float3 normalWS = normalize(input.normalWS);

    // URP 라이팅 데이터(메인 라이트 방향/색상/그림자 감쇠)는 GetMainLight()로 가져온다.
    // shadowCoord를 함께 넘기면 shadowAttenuation에 그림자맵 결과가 반영된다
    Light mainLight = GetMainLight(input.shadowCoord);

    half NdotL = dot(normalWS, mainLight.direction);
    half litMask = NdotL * mainLight.shadowAttenuation;

    // smoothstep으로 경계를 완만하게 처리한 2-step 밴딩 (완전 계단식이 필요하면 step()으로 교체)
    half lightBand = smoothstep(_ShadowThreshold - _ShadowSmoothness, _ShadowThreshold + _ShadowSmoothness, litMask);

    half3 shading = lerp(_ShadowColor.rgb, mainLight.color, lightBand);
    half3 albedo = baseColor.rgb * shading;

    // 림 라이트: 시야 방향과 노멀이 수직에 가까울수록(가장자리) 밝아진다. 그림자 영역에는 가산하지 않는다
    float3 viewDirWS = normalize(GetCameraPositionWS() - input.positionWS);
    half rim = 1.0 - saturate(dot(viewDirWS, normalWS));
    half rimBand = smoothstep(_RimThreshold - _RimSmoothness, _RimThreshold + _RimSmoothness, rim) * lightBand;

    half3 finalColor = albedo + _RimColor.rgb * rimBand;

    return half4(finalColor, baseColor.a);
}

#endif
```

### 7-4. `ToonOutlineFullScreen.shader` — 화면공간 외곽선 (신규, 6절 근거로 Inverted Hull 대체)

이 파일은 `ToonLit.shader`와 별개의 독립된 `.shader`다(머티리얼별로 붙는 게 아니라 `ToonOutline_Mat.mat` 머티리얼 하나로 카메라 전체에 적용되므로 `ToonLitInput.hlsl`을 공유하지 않는다). Roberts Cross 방식(대각선 2쌍의 깊이/노멀 차이 비교)으로 간단하고 가벼운 엣지 검출을 수행한다.

```hlsl
Shader "Custom/ToonOutlineFullScreen"
{
    Properties
    {
        _OutlineColor("Outline Color", Color) = (0, 0, 0, 1)
        _DepthThreshold("Depth Threshold", Range(0.0001, 0.1)) = 0.01
        _NormalThreshold("Normal Threshold", Range(0, 1)) = 0.4
    }

    SubShader
    {
        Tags { "RenderType" = "Opaque" "RenderPipeline" = "UniversalPipeline" }

        Pass
        {
            Name "ToonOutlineFullScreen"
            ZTest Always
            ZWrite Off
            Cull Off

            HLSLPROGRAM
            #pragma vertex Vert
            #pragma fragment ToonOutlineFullScreenFragment

            // Vert()/Varyings/_BlitTexture는 URP 코어의 Blit.hlsl이 제공 (5-1절 근거)
            #include "Packages/com.unity.render-pipelines.core/Runtime/Utilities/Blit.hlsl"
            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"
            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/DeclareDepthTexture.hlsl"
            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/DeclareNormalsTexture.hlsl"

            CBUFFER_START(UnityPerMaterial)
                half4 _OutlineColor;
                half _DepthThreshold;
                half _NormalThreshold;
            CBUFFER_END

            half4 ToonOutlineFullScreenFragment(Varyings input) : SV_Target
            {
                float2 uv = input.texcoord;
                half4 sceneColor = SAMPLE_TEXTURE2D_X_LOD(_BlitTexture, sampler_PointClamp, uv, 0);

                // 인접 픽셀 오프셋 (화면 해상도 기준 1텍셀)
                float2 texel = _BlitTexture_TexelSize.xy;

                // Roberts Cross: 대각선 방향 2쌍의 샘플을 비교해 깊이/노멀이 급격히 변하는 지점(=윤곽선)을 찾는다
                float depthTL = SampleSceneDepth(uv + texel * float2(-1, -1));
                float depthBR = SampleSceneDepth(uv + texel * float2( 1,  1));
                float depthTR = SampleSceneDepth(uv + texel * float2( 1, -1));
                float depthBL = SampleSceneDepth(uv + texel * float2(-1,  1));
                float depthEdge = abs(depthTL - depthBR) + abs(depthTR - depthBL);

                float3 normalTL = SampleSceneNormals(uv + texel * float2(-1, -1));
                float3 normalBR = SampleSceneNormals(uv + texel * float2( 1,  1));
                float3 normalTR = SampleSceneNormals(uv + texel * float2( 1, -1));
                float3 normalBL = SampleSceneNormals(uv + texel * float2(-1,  1));
                float normalEdge = length(normalTL - normalBR) + length(normalTR - normalBL);

                // 둘 중 하나라도 임계값을 넘으면 외곽선으로 판단 (깊이만으로는 같은 평면 위의 그림 경계를 못 잡고,
                // 노멀만으로는 평행한 면이 겹쳐진 경우를 못 잡기 때문에 두 기준을 함께 사용한다)
                half edge = saturate(step(_DepthThreshold, depthEdge) + step(_NormalThreshold, normalEdge));

                return lerp(sceneColor, _OutlineColor, edge);
            }
            ENDHLSL
        }
    }
}
```

> **주의(9절 근거로 상세 서술)**: 위 깊이 비교는 원시(raw, non-linear) 깊이값을 그대로 뺄셈하는 단순한 방식이라, 카메라와의 거리에 따라 `_DepthThreshold`가 필요 이상으로 민감하거나 둔감해질 수 있다. 구현 단계에서 실제 씬 스케일에 맞춰 `_DepthThreshold`/`_NormalThreshold` 값을 튜닝하는 과정이 필요하다.

### 7-5. `ToonShadowCasterPass.hlsl` / `ToonDepthOnlyPass.hlsl` / `ToonDepthNormalsPass.hlsl` (골격)

세 Pass는 URP 표준 패턴(코어 라이브러리의 `ApplyShadowBias`/`TransformWorldToHClip` 유틸 재사용)을 따르는 최소 구현으로 작성한다. 예시로 `ToonShadowCasterPass.hlsl`:

```hlsl
#ifndef TOON_SHADOW_CASTER_PASS_INCLUDED
#define TOON_SHADOW_CASTER_PASS_INCLUDED

struct ShadowVaryings
{
    float4 positionHCS : SV_POSITION;
};

ShadowVaryings ToonShadowVertex(Attributes input)
{
    ShadowVaryings output = (ShadowVaryings)0;

    VertexPositionInputs positionInputs = GetVertexPositionInputs(input.positionOS.xyz);
    VertexNormalInputs normalInputs = GetVertexNormalInputs(input.normalOS);

    // 그림자맵 접선 방향 왜곡(피터패닝)을 줄이기 위해 URP 표준 바이어스 함수를 사용한다
    float3 biasedPositionWS = ApplyShadowBias(positionInputs.positionWS, normalInputs.normalWS, GetMainLight().direction);
    output.positionHCS = TransformWorldToHClip(biasedPositionWS);

    return output;
}

half4 ToonShadowFragment(ShadowVaryings input) : SV_TARGET
{
    return 0;
}

#endif
```

`ToonDepthOnlyPass.hlsl`/`ToonDepthNormalsPass.hlsl`도 동일하게 `GetVertexPositionInputs`로 클립공간 위치만 출력하는 최소 버텍스 함수와 빈 프래그먼트(또는 `DepthNormals`의 경우 `normalWS`를 출력)로 구성한다. **주의: 위 3개 Pass의 정확한 URP 내부 함수/매크로 이름은 설치된 URP 패키지 버전에 따라 미세하게 다를 수 있으므로, Unity Editor에서 실제 컴파일해보며 오류가 나는 심볼을 해당 버전의 `Packages/com.unity.render-pipelines.universal/Shaders/ShadowCasterPass.hlsl` 등 원본과 대조해 보정하는 작업이 구현 단계에서 필요하다.**

### 7-6. 기존 머티리얼 적용 및 외곽선 Renderer Feature 등록 절차 (사용자 승인 완료, 진행 가능)

**A. 셀 셰이딩(라이팅) 적용 — 머티리얼별**

1. `Assets/03_Shaders/`에 3절의 신규 파일 7개(`ToonLit.shader`, `ToonLitInput.hlsl`, `ToonLitForwardPass.hlsl`, `ToonOutlineFullScreen.shader`, `ToonShadowCasterPass.hlsl`, `ToonDepthOnlyPass.hlsl`, `ToonDepthNormalsPass.hlsl`) 생성 및 Unity Editor에서 컴파일 오류 없는지 확인.
2. `Assets/Blender/Mat/Rat_Mat.mat` 선택 → Inspector 상단 Shader 드롭다운 → `Custom/ToonLit`으로 변경.
3. `_BaseMap` 슬롯에 `RatCharacter.png`가 그대로 유지되는지 확인. 유지되지 않으면 텍스처를 재드래그.
4. `_ShadowColor`, `_ShadowThreshold`, `_RimColor` 등 신규 프로퍼티 초기값을 씬 조명에 맞춰 조정.
5. 나머지 6개 머티리얼(`Cat_Mat`, `Oven_Mat`, `Sink_Mat`, `Table&Chair_Mat`, `refrigerator_Mat`, `Wall_Mat`)에도 2~4단계를 반복. 각 `_BaseMap` 텍스처가 유지되는지 개별 확인(`Wall_Mat`은 원래 텍스처가 없으므로 `_BaseColor`만 조정).

**B. 외곽선 Renderer Feature 등록 — 씬 전체 1회 설정 (6절/5-1절 근거)**

6. `Assets/03_Shaders/ToonOutline_Mat.mat` 신규 머티리얼 생성 → Shader를 `Custom/ToonOutlineFullScreen`으로 지정, `_OutlineColor`/`_DepthThreshold`/`_NormalThreshold` 초기값 설정.
7. `Assets/Settings/PC_Renderer.asset` 선택 → Inspector에서 **Add Renderer Feature → Full Screen Pass Renderer Feature** 추가.
8. 추가된 Renderer Feature의 `Requirements`에 **Depth**, **Normal** 체크, `Pass Material`에 `ToonOutline_Mat.mat` 연결, `Injection Point`는 기본값(`After Rendering Post Processing`) 또는 `Before Rendering Post Processing` 중 결과를 보고 선택.
9. Game 뷰 또는 Play 모드에서 Directional Light를 회전시켜가며 밴딩 경계/림 라이트가 캐릭터와 환경 오브젝트 모두에서 의도대로 보이는지, 외곽선이 씬 전체 오브젝트 경계에 고르게 나타나는지(특히 새로 추가한 오브젝트에도 별도 설정 없이 적용되는지) 육안 확인. `_DepthThreshold`/`_NormalThreshold`를 씬 스케일에 맞춰 튜닝(7-4절 주의사항 참고).
10. `PC_Renderer.asset`가 실제로 사용 중인 Graphics/Quality 설정에서 기존 SSAO와 신규 외곽선 포스트프로세스가 함께 정상 렌더링되는지 확인(1-1절 근거, PC 한정이므로 Mobile 전환 테스트는 이번 범위에서 생략).

## 9. 주의 사항 및 설계 결정 근거

1. **`.shader` + 개별 `.hlsl` 분리 구조를 채택한 이유**: URP `Lit.shader`가 따르는 표준 패턴이며, Pass별 로직을 독립된 파일로 분리해 두면 캐릭터 2종과 환경 오브젝트 5종이 동일한 `ToonLit.shader` 하나를 공유하면서도, 이후 특정 오브젝트군(예: 환경 전용)에만 다른 파라미터/로직이 필요해질 때 `ToonLitForwardPass.hlsl` 등 로직 파일 일부만 교체·재사용하기 쉽다.
2. **외곽선을 Inverted Hull 대신 Renderer Feature(화면공간 Depth/Normal Edge Detection)로 채택한 이유(2026-09-12 변경)**: 최초 계획에서는 적용 대상이 7개 머티리얼로 고정되어 있다고 보고 머티리얼 단위로 끝나는 Inverted Hull을 채택했으나, 사용자로부터 "이후 오브젝트를 계속 추가할 예정이므로 씬 전체에 적용되는 방식으로 해달라"는 요청을 받아 화면공간 방식으로 변경했다. Inverted Hull은 새 오브젝트가 추가될 때마다 그 머티리얼에 `Outline` Pass를 넣어줘야 하지만, 화면공간 방식은 `PC_Renderer.asset`에 Renderer Feature 하나만 등록해 두면 `DepthNormals` Pass를 가진 셰이더(`Custom/ToonLit`)를 쓰는 모든 신규 오브젝트에 자동으로 적용된다. URP 17.3.0(설치된 버전, `Library/PackageCache`에서 직접 확인)에 이 목적의 **내장 `FullScreenPassRendererFeature`**가 있어 C# 코드를 새로 작성할 필요가 없다는 것도 확인했다(5-1절 근거). 다만 화면공간 Depth/Normal Edge Detection은 **카메라와 거리가 먼 오브젝트일수록 원시 깊이값의 변화 폭이 작아져 `_DepthThreshold`가 씬 전체 스케일에 걸쳐 고르게 작동하지 않을 수 있고**, 서로 다른 오브젝트가 화면상 겹쳐 보일 때 실제로는 따로 그려도 될 경계가 안 잡히는 등 Inverted Hull과는 다른 종류의 튜닝 이슈가 있다(7-4절 주의사항 참고). 이 부분은 구현 단계에서 실제 씬(부엌 배경 + 캐릭터)을 보며 임계값을 조정해야 한다.
3. **메인 라이트만 지원, Additional Light 미지원**: 현재 씬에는 Directional Light 하나만 확인되어 범위를 좁혔다. 부엌 배경에 포인트 라이트(조명 기구 등)가 추가되면 `ForwardFragment`에 `GetAdditionalLightsCount()`/`GetAdditionalLight()` 루프를 추가하는 확장 작업이 별도로 필요하다.
4. **`DepthNormals` Pass를 포함한 이유**: 이번 범위인 `PC_Renderer.asset`이 SSAO Renderer Feature를 사용 중이며 SSAO는 노멀 버퍼(`DepthNormals` Pass 결과)에 의존한다. 이 Pass가 없으면 캐릭터/환경 오브젝트가 SSAO 계산에서 제외되거나 경고가 발생할 수 있어 포함했다. **2026-09-12 변경 이후로는 신규 외곽선 포스트프로세스(`ToonOutlineFullScreen.shader`)도 같은 `DepthNormals` 결과(`_CameraNormalsTexture`)를 사용하므로, 이 Pass의 중요도가 SSAO 호환용에서 "셀 셰이딩 + 외곽선 두 기능의 공통 데이터 소스"로 격상됐다(2절/6절 근거).** (Mobile 렌더러는 이번 범위 밖이라 별도 고려하지 않았다 — 1-1절 근거.)
5. **N-step을 2단계로 제한한 이유**: 저해상도 스타일라이즈드 캐릭터에서는 3단계 이상의 밴딩이 오히려 텍스처 디테일과 충돌해 지저분해 보일 위험이 있다. `_ShadowThreshold`/`_ShadowSmoothness`를 머티리얼 프로퍼티로 노출해 두었으므로, 추후 3단계(중간톤 추가)로 확장하고 싶다면 `lightBand` 계산부에 두 번째 `smoothstep` 임계값만 추가하면 된다(하드코딩 대신 확장 가능한 구조로 설계).
6. **SRP Batcher 호환을 위해 모든 머티리얼 프로퍼티를 `CBUFFER_START(UnityPerMaterial)` 안에 선언**: URP는 SRP Batcher를 기본 활성화하는데, 프로퍼티가 이 CBUFFER 밖에 선언되면 배칭이 깨져 드로우콜이 늘어난다. 7개 머티리얼(캐릭터 2종 + 환경 5종)이 모두 같은 셰이더를 공유하므로, SRP Batcher가 정상 동작해야 드로우콜 절감 효과를 제대로 얻을 수 있어 처음부터 규칙을 지켰다.
7. **기존 `_BaseMap` 프로퍼티명을 그대로 재사용**: URP Lit과 동일한 이름(`_BaseMap`)을 채택해, 머티리리얼의 Shader를 교체할 때 Unity 에디터가 동일 이름의 텍스처 프로퍼티를 최대한 유지 시도하도록 했다(완전 자동 보장은 아니므로 7-6절에서 수동 확인 절차를 명시함).
8. **파일 수정 규칙 준수**: 대상 7개 `.mat` 파일은 사용자가 직접 만들었다고 확정할 수 없는 파일(FBX 임포트 자동 생성 가능성)이었으나, 2026-09-12에 사용자로부터 이 7개 파일의 Shader 교체에 대한 명시적 승인을 받았다(2절 참고). `PC_Renderer.asset`(외곽선 Renderer Feature 등록 대상, 4절 근거)도 사용자가 직접 만든 파일은 아니므로, 실제 수정 전 별도 확인이 필요하면 요청할 것. 이 계획 문서 자체에서는 실제 파일 수정을 수행하지 않았으며, 4절/7-6절에 정리된 절차대로 구현 단계에서 진행한다.
9. **HLSL 심볼명 검증 필요성 명시**: 이 계획에 작성된 HLSL 코드는 URP의 일반적으로 안정적인 공개 API를 기준으로 작성했다. `ToonLit.shader` 계열(`GetMainLight`, `GetVertexPositionInputs`, `TransformWorldToShadowCoord`, `ApplyShadowBias` 등)은 일반적으로 안정적인 URP 공개 API지만 정확한 시그니처는 패키지 버전에 따라 미세한 차이가 있을 수 있어 구현 단계에서 컴파일 확인이 필요하다. 반면 `ToonOutlineFullScreen.shader`가 쓰는 `Vert`/`Varyings`/`_BlitTexture`(`Blit.hlsl`)와 `SampleSceneDepth`/`SampleSceneNormals`(`DeclareDepthTexture.hlsl`/`DeclareNormalsTexture.hlsl`), `FullScreenPassRendererFeature`는 이번에 설치된 URP 17.3.0 패키지 소스(`Library/PackageCache/com.unity.render-pipelines.universal@8a9b4021522a`, `com.unity.render-pipelines.core@c3bbbae46ff1`)를 **직접 열어 실제 함수 시그니처를 확인한 뒤 작성**했다(5-1절/7-4절 근거) — 이 부분은 추측이 아니라 소스 확인 완료.
