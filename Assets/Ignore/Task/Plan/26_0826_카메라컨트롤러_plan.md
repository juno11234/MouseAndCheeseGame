# 카메라 컨트롤러(벽 충돌 방지) 기능 구현 계획

- 작성 날짜: 2026-08-26 (26_0826)
- 작성자: planner (Claude Code)
- 배경: `Player.cs`가 A/D 입력으로 Player 루트를 직접 회전시키던 기존 설계에서, Camera가 Player의 자식(로컬 오프셋 `(0, 3.25, -5.35)`, 피벗 반경 약 6.3유닛)으로 매달려 있어 회전 시 카메라가 큰 호를 그리며 씬의 "Kitchen" 지오메트리를 관통하고, Near Clip Plane(0.3)이 이를 잘라내 "칼로 자른 듯" 보이는 문제가 발생했다.
- 요청 범위: (1) 좌우 회전 책임을 Player → Camera 쪽으로 이전, (2) Player는 전진 이동만 담당, (3) SphereCast 기반 카메라-벽 충돌 회피(클리핑 방지) 도입. LockOn/Q·E 타겟 전환/마우스 pitch 조작은 범위 밖.

## 1. 코드베이스 재조사 결과

### 1-1. `Assets/02_Scripts/Input/InputManager.cs` (현재 상태, 변경 없음)
- `PlayerInput.PlayerActionsActions`(액션 맵 `PlayerActions`)을 구독하는 순수 입력 수집기.
- `Move` 액션(2D Vector, W/A/S/D 컴포지트)의 `performed`/`canceled`를 구독해 `public Vector2 MoveInput { get; private set; }` 하나만 제공한다. 해석(회전/이동 등 의미 부여)은 하지 않는다.
- `Look` 액션(마우스 delta)도 정의되어 있으나 `InputManager`는 아직 구독하지 않는다(마우스 조작은 이번 범위 밖이므로 그대로 미사용 유지).

### 1-2. `Assets/02_Scripts/Player.cs` (현재 상태)
- `[RequireComponent(typeof(CharacterController))]`, `CharacterController`를 `Awake()`에서 캐싱.
- `HandleRotation()`: `MoveInput.x`(A/D)로 `transform.Rotate(Vector3.up, x * _turnSpeed * dt, Space.World)` → **이 부분이 이번 요청에 따라 제거 대상**.
- `HandleMovement()`: `MoveInput.y`(W, 음수는 `Mathf.Max(0f, y)`로 차단)로 `transform.forward * forwardInput`을 `CharacterController.Move()`에 전달 → **이동 방향의 기준을 `transform.forward`에서 카메라의 수평 정면 방향으로 교체**.
- 필드: `_inputManager`(SerializeField), `_moveSpeed = 5`, `_turnSpeed = 180`(씬에는 `_moveSpeed = 20`으로 오버라이드되어 있음).

## 4. 단계별 구현 내용

### 4-1. 씬 계층 구조 변경 설계 (코드 작성 전 전제 조건)

현재: `Player → Main Camera` (Camera가 Player 루트에 직접 매달림, 회전 시 반경 6.3유닛으로 공전)

변경 후:
```
Player (회전 없음, CharacterController로 위치만 이동)
├─ Capsule
└─ CameraPivot (신규, local pos (0, 3.25, 0), local rot identity)  ← CameraController.cs 부착, A/D로 Y축 회전
     └─ Main Camera (local pos (0, 0, -5.35), local rot 기존 유지(X≈2.529° tilt))
```
- `CameraPivot`을 Camera 높이(3.25)에 두고, Camera는 그 아래에서 Z축으로만 `-5.35` 떨어뜨린다. 피벗 회전각 0일 때 Camera의 월드 위치는 기존과 완전히 동일(`Player.pos + (0,3.25,-5.35)`)하므로 도입 시 시각적 점프가 없다.
- Camera의 기존 로컬 회전(약간의 하향 tilt)은 그대로 유지한다. `CameraController`는 `_cameraTransform.rotation`을 건드리지 않고 `.position`만 갱신하므로, 피벗의 Y축 회전과 Camera 자체의 고정 tilt가 합성되어 "항상 플레이어를 살짝 내려다보며 공전"하는 기존 느낌이 유지된다.

### 4-2. `CameraController.cs` 신규 작성

`Assets/02_Scripts/CameraController.cs`

```csharp
using UnityEngine;

/// <summary>
/// InputManager로부터 좌우 회전 입력을 받아 카메라 피벗(자신)을 Y축 회전시키고,
/// SphereCast로 벽 등 지오메트리와의 충돌을 검사해 카메라가 벽을 뚫고 들어가는
/// 클리핑 현상을 방지하는 클래스. 이 스크립트는 카메라 피벗(CameraPivot) 오브젝트에 부착한다.
/// </summary>
public class CameraController : MonoBehaviour
{
    [SerializeField] private InputManager _inputManager;
    [SerializeField] private Transform _cameraTransform;
    [SerializeField] private float _rotationSpeed = 180f;

    [Header("벽 충돌 회피 설정")]
    [SerializeField] private LayerMask _collisionLayerMask;
    [SerializeField] private float _collisionRadius = 0.3f;
    [SerializeField] private float _collisionBuffer = 0.2f;
    [SerializeField] private float _minDistance = 0.5f;
    [SerializeField] private float _cameraSmoothSpeed = 15f;

    private float _defaultDistance;
    private Vector3 _cameraVelocity;

    /// <summary>
    /// 카메라 피벗이 현재 바라보는 수평(Y=0으로 투영) 정면 방향. Player의 전진 이동 방향 계산에 사용된다.
    /// 매 호출 시 최신 회전값으로 즉시 계산되는 프로퍼티이며, 별도로 캐싱하지 않는다
    /// (Update 실행 순서에 따른 한 프레임 지연 문제를 피하기 위함, 6-6절 근거 참고)
    /// </summary>
    public Vector3 ForwardDirection
    {
        get
        {
            Vector3 flatForward = transform.forward;
            flatForward.y = 0f;
            return flatForward.normalized;
        }
    }

    /// <summary>
    /// 피벗과 카메라 사이의 기본(충돌 없을 때) 거리를 최초 배치된 로컬 위치 기준으로 측정한다
    /// </summary>
    private void Start()
    {
        if (_cameraTransform == null)
        {
            return;
        }

        _defaultDistance = Vector3.Distance(transform.position, _cameraTransform.position);
    }

    /// <summary>
    /// 매 프레임 좌우 회전 입력을 처리한다
    /// </summary>
    private void Update()
    {
        HandleRotation();
    }

    /// <summary>
    /// 모든 Update가 끝난 뒤(Player 이동 반영 후) 벽 충돌 검사를 수행한다
    /// </summary>
    private void LateUpdate()
    {
        HandleCollision();
    }

    /// <summary>
    /// MoveInput의 X값(A/D)으로 카메라 피벗을 Y축 기준 좌우 회전시킨다
    /// </summary>
    private void HandleRotation()
    {
        if (_inputManager == null)
        {
            return;
        }

        float turnInput = _inputManager.MoveInput.x;
        transform.Rotate(Vector3.up, turnInput * _rotationSpeed * Time.deltaTime, Space.World);
    }

    /// <summary>
    /// 피벗에서 카메라 방향(-forward)으로 SphereCast를 쏘아 벽 등 지오메트리에 닿으면
    /// 카메라와의 목표 거리를 줄여, 카메라가 지오메트리를 뚫고 들어가는 현상을 방지한다
    /// </summary>
    private void HandleCollision()
    {
        if (_cameraTransform == null)
        {
            return;
        }

        Vector3 direction = -transform.forward;
        float targetDistance = _defaultDistance;

        bool isHit = Physics.SphereCast(transform.position, _collisionRadius, direction,
            out RaycastHit hit, _defaultDistance, _collisionLayerMask);

        if (isHit == true)
        {
            targetDistance = Mathf.Max(_minDistance, hit.distance - _collisionBuffer);
        }

        Vector3 targetPosition = transform.position + direction * targetDistance;
        _cameraTransform.position = Vector3.SmoothDamp(_cameraTransform.position, targetPosition,
            ref _cameraVelocity, 1f / _cameraSmoothSpeed);
    }
}
```

### 4-3. `Player.cs` 수정

`Assets/02_Scripts/Player.cs` (전체 대체 — 실제 적용은 사용자 승인 후 진행)

```csharp
using UnityEngine;

/// <summary>
/// InputManager로부터 전진 입력을 받아, CameraController가 바라보는 방향으로
/// CharacterController를 이용해 전진 이동만 처리하는 클래스
/// </summary>
[RequireComponent(typeof(CharacterController))]
public class Player : MonoBehaviour
{
    [SerializeField] private InputManager _inputManager;
    [SerializeField] private CameraController _cameraController;
    [SerializeField] private float _moveSpeed = 5f;

    private CharacterController _characterController;

    /// <summary>
    /// 같은 GameObject에 부착된 CharacterController 컴포넌트를 캐싱한다
    /// </summary>
    private void Awake()
    {
        _characterController = GetComponent<CharacterController>();
    }

    /// <summary>
    /// 매 프레임 전진 이동 처리를 수행한다
    /// </summary>
    private void Update()
    {
        HandleMovement();
    }

    /// <summary>
    /// MoveInput의 Y값(W)이 양수일 때만, CameraController가 바라보는 수평 방향으로
    /// CharacterController를 이용해 전진 이동을 처리한다. 음수(S, 후진 입력)는 무시한다
    /// </summary>
    private void HandleMovement()
    {
        if (_inputManager == null || _characterController == null || _cameraController == null)
        {
            return;
        }

        float forwardInput = Mathf.Max(0f, _inputManager.MoveInput.y);
        Vector3 moveDirection = _cameraController.ForwardDirection * forwardInput;
        _characterController.Move(moveDirection * (_moveSpeed * Time.deltaTime));
    }
}
```

### 4-4. Unity Editor 수동 작업 (코드 외 작업)

1. **CameraPivot 생성**: `Player` 하위에 빈 GameObject `CameraPivot` 생성, Local Position `(0, 3.25, 0)`, Local Rotation `(0,0,0)`으로 설정.
2. **Main Camera 재배치**: `Main Camera`를 `CameraPivot`의 자식으로 드래그. Local Position을 `(0, 0, -5.35)`로 변경. Local Rotation(약 X 2.529° tilt)은 기존 값을 그대로 둔다.
3. **CameraController 부착**: `CameraPivot`에 `Add Component` → `CameraController`.
   - `_inputManager`: `Player`의 `InputManager` 컴포넌트를 드래그 연결.
   - `_cameraTransform`: 자식 `Main Camera`의 Transform을 드래그 연결.
   - `_rotationSpeed`: 180 (기존 `Player._turnSpeed`와 동일 값으로 시작, 필요 시 조정).
   - `_collisionRadius`: 0.3 (Camera의 Near Clip Plane 값 0.3과 동일하게 맞춰, SphereCast가 통과시키는 여유 공간이 실제 렌더링 클리핑 임계값과 정합되도록 함).
   - `_collisionBuffer`: 0.2, `_minDistance`: 0.5, `_cameraSmoothSpeed`: 15 (참고 스크립트 기본값과 동일하게 시작).
   - `_collisionLayerMask`: **아래 4번 작업 완료 후** 벽/가구용 레이어만 선택.
4. **(선행 필요) 벽/가구 Collider 및 전용 Layer 추가** — 이번 계획의 핵심 전제 조건:
   - 현재 Kitchen 하위에는 바닥 `Plane`의 `MeshCollider` 외에 벽/냉장고 등에 Collider가 전혀 없다. `Edit > Project Settings > Tags and Layers`에서 예: `Environment` 레이어를 신설하고, Kitchen의 벽/가구 GameObject에 `BoxCollider`/`MeshCollider`를 추가한 뒤 해당 레이어로 지정한다.
   - `CameraController._collisionLayerMask`는 이 `Environment` 레이어만 포함하고 `Player`가 속한 Layer(현재 Default/0)는 **제외**한다. 그렇지 않으면 SphereCast가 Player 자신의 `CharacterController` 콜라이더를 맞혀 오작동할 수 있다(6-7절 근거 참고).
5. **Player 컴포넌트 필드 갱신**: `Player` 인스펙터에서 `_cameraController` 필드에 `CameraPivot`의 `CameraController` 컴포넌트를 드래그 연결. (기존 `_turnSpeed` 필드는 코드에서 제거되므로 Inspector에서 자동으로 사라진다.)

> 씬 파일(.unity)은 YAML 직접 편집 대신 Editor UI로 작업할 것을 권장한다(GUID/fileID 불일치로 인한 씬 손상 위험 회피, 기존 WASD 계획과 동일한 원칙).

## 5. 데이터 흐름 설명

```
[A/D 키 입력]                                    [W 키 입력]
      ↓                                                ↓
Unity Input System (PlayerActions.Move, 2D Vector 컴포지트)
      ↓ performed/canceled                            ↓ performed/canceled
InputManager.MoveInput (Vector2, 원본 값)  ─────────────┘
      ↓ 매 프레임 읽기 (.x)                              ↓ 매 프레임 읽기 (.y)
CameraController.Update()                        Player.Update()
  └─ HandleRotation()                               └─ HandleMovement()
       - MoveInput.x → transform.Rotate(Y축)              - Mathf.Max(0, MoveInput.y)로 후진 차단
       - CameraPivot(this)의 회전만 갱신                    - _cameraController.ForwardDirection 조회
                                                            (CameraPivot.transform.forward를 Y=0
                                                             투영·정규화한 값, 항상 최신 회전 반영)
                                                          - CharacterController.Move(방향 * 속도 * dt)
      ↓ (모든 Update 종료 후)
CameraController.LateUpdate()
  └─ HandleCollision()
       - direction = -CameraPivot.forward
       - Physics.SphereCast(피벗 위치, radius, direction, _defaultDistance, 벽 레이어)
       - 충돌 시: targetDistance = max(minDistance, hit.distance - buffer)
       - 미충돌 시: targetDistance = _defaultDistance(기본 배치 거리)
       - Main Camera.position = SmoothDamp(현재 위치 → 피벗 + direction*targetDistance)
      ↓
씬 상의 실제 Player 이동 결과(CharacterController) + 벽에 뚫리지 않는 Camera 위치
```

핵심 변경점: 이전에는 A/D가 Player 루트를 직접 회전시켜 Camera가 반경 6.3유닛으로 공전하며 벽을 관통했다. 이제 A/D는 `CameraPivot`(별도 오브젝트)만 회전시키고, Camera는 SphereCast로 매 프레임 벽까지의 거리를 검사해 스스로 거리를 좁히므로 관통이 발생하지 않는다. W 이동은 Player 자신의 고정된 `transform.forward`가 아니라 `CameraController.ForwardDirection`(카메라가 현재 바라보는 수평 방향)을 사용한다.

## 6. 주의 사항 및 설계 결정 근거

1. **회전 책임 이전 대상 = "새 CameraPivot 오브젝트"이지 "Player 루트"가 아님**: 만약 `CameraController`가 여전히 Player 루트를 회전시키는 방식으로만 옮겨졌다면, Camera는 여전히 Player 루트 자식으로서 동일한 반경(6.3유닛)으로 공전해 벽 관통 문제가 그대로 재현된다. 따라서 회전과 시각적 공전 반경을 분리하기 위해 `CameraPivot`이라는 새 자식 오브젝트를 도입하고, Player 루트 자체는 더 이상 회전하지 않도록 설계했다. 이것이 클리핑 문제의 근본 해결에 필수적인 구조 변경이다.
2. **이동 방향 정책: "카메라 회전 방향을 향해 전진" 채택 (요청 3번 검토 결과)**: 두 가지 대안을 검토했다.
   - (A) 플레이어가 제자리에서 카메라만 도는 방식(이동 방향이 카메라 회전과 무관하게 고정): 사용자가 A/D로 화면을 돌린 뒤 W를 눌러도 화면상 정면과 다른 방향으로 이동해 조작감이 어긋난다. 기각.
   - (B) 카메라가 바라보는 수평 방향으로 전진(채택): 일반적인 3인칭 카메라 상대 이동(camera-relative movement) 컨벤션과 일치하며, "A/D로 돌린 방향 = W로 나아가는 방향"이라는 기존(회전 이전 전) 사용자 기대를 그대로 보존한다. `CameraController.ForwardDirection`(피벗의 `transform.forward`를 Y=0 평면에 투영·정규화한 값)을 `Player.HandleMovement()`가 사용하도록 설계했다.
   - 참고로 `Capsule` 자식 메시는 Y축 대칭 형태(캡슐)라 Player 루트가 더 이상 회전하지 않아도 시각적으로 "방향을 안 보는" 위화감은 없다. 추후 방향성이 있는 캐릭터 모델을 도입하면 이동 방향에 맞춰 Player 루트(또는 모델 자식)를 별도로 회전시키는 로직이 필요할 수 있으나, 이는 이번 범위 밖이다.
3. **`InputManager.cs`는 수정하지 않고 기존 `MoveInput.x`를 재사용 (요청 6번)**: A/D는 이미 `PlayerActions.Move` 액션(2D Vector 컴포지트)의 X축으로 수집되고 있으며, 이번 요청은 "같은 원본 입력을 소비하는 주체"만 Player에서 CameraController로 바뀌는 것이지 새로운 물리 키 입력이 추가되는 것이 아니다. 따라서 새 Input Action이나 새 프로퍼티를 추가할 필요가 없고, `CameraController`가 `Player`와 동일한 `InputManager` 인스턴스를 `[SerializeField]`로 참조해 `MoveInput.x`를 그대로 읽도록 설계했다. 입력 수집(원본 값 제공)과 입력 해석(회전/이동 정책)의 책임 분리 원칙은 기존 WASD 계획과 동일하게 유지된다.
4. **SphereCast 기반 충돌 회피 로직은 참고 스크립트의 `CameraCollision()`을 그대로 채택하되 `_minDistance` 클램프를 추가**: 참고 스크립트는 `hit.distance - collideOffset`을 그대로 목표 거리로 사용해, 카메라가 벽에 매우 가깝게 붙는 극단적 상황(예: 플레이어가 구석에 몰릴 때)에서 목표 거리가 지나치게 짧아지거나 음수에 가까워질 위험이 있다. 이를 방지하기 위해 `Mathf.Max(_minDistance, hit.distance - _collisionBuffer)`로 하한을 두어, 카메라가 피벗(플레이어) 위치를 뚫고 반대편으로 넘어가거나 Player 캡슐 내부로 파고드는 것을 방지했다. 다만 극단적인 좁은 구석에서는 `_minDistance`로 인해 벽이 살짝 보이는 정도의 잔여 클리핑은 남을 수 있으며, 이는 완전한 카메라-충돌 없음을 보장하기보다 "전체 화면이 잘려나가는" 심각한 클리핑을 방지하는 데 초점을 둔 설계 트레이드오프임을 명시한다.
5. **씬에 벽/가구 Collider가 없는 상태 확인 (중요 전제 조건)**: `Assets/01_Scenes/SampleScene.unity`와 `Assets/Blender/refrigerator_Prefab.prefab`을 직접 검사한 결과, Kitchen 하위에는 바닥 `Plane`의 `MeshCollider` 외에 어떤 벽/가구 Collider도 존재하지 않는다. 이번 계획의 코드(`CameraController.cs`)는 SphereCast로 지정된 Layer의 Collider를 검사하는 로직만 제공하며, 실제로 벽을 감지하려면 4-4절의 4번 작업(Kitchen 벽/가구에 Collider 및 전용 Layer 추가)이 **선행**되어야 기능이 의미 있게 동작한다. 이 작업 없이는 코드가 정상 동작하더라도 바닥 외에는 아무것도 감지하지 못한다.
6. **`ForwardDirection`을 캐시 필드 대신 매번 계산하는 프로퍼티로 설계**: 만약 `HandleRotation()` 안에서 회전 후 결과를 필드에 캐싱해두고 `Player`가 그 필드를 읽는 방식이었다면, Unity가 서로 다른 `MonoBehaviour`의 `Update()` 호출 순서를 프로젝트 설정(Script Execution Order) 없이는 보장하지 않으므로, `Player.Update()`가 `CameraController.Update()`보다 먼저 실행될 경우 한 프레임 지연된(스테일) 회전 값을 사용하게 될 위험이 있다. 이를 원천 차단하기 위해 `ForwardDirection`을 캐시 필드가 아닌 매 접근 시 `transform.forward`를 즉시 계산하는 get-전용 프로퍼티로 설계했다. 이 경우 Script Execution Order를 별도로 설정할 필요가 없다.
7. **`_collisionLayerMask`에서 Player 자신의 Layer를 반드시 제외해야 함**: 프로젝트에는 현재 `Default`/`TransparentFX`/`Ignore Raycast`/`Water`/`UI` 레이어만 정의되어 있고 모든 GameObject(Player 포함)가 `Default`(레이어 0)이다. `CameraPivot`은 Player의 자식이므로 SphereCast 시작점이 Player의 `CharacterController` 콜라이더 바로 위(피벗 높이 3.25는 캡슐 상단 y=2보다 높아 통상적으로는 자기 충돌 가능성이 낮음)에 위치하지만, 만약 `_collisionLayerMask`를 `Default`(Everything)로 설정하면 Player 자신의 콜라이더를 맞혀 오작동할 위험이 있다. 이를 피하기 위해 4-4절 4번에서 전용 `Environment` 레이어 신설과 마스크 설정을 명시했다.
8. **CameraController 부착 위치를 `CameraPivot`으로 결정한 이유**: 참고 스크립트는 별도의 "리그 루트" GameObject에 스크립트를 붙이고 `cameraPivot`/`cameraTransform`을 각각 필드로 참조하는 3단 구조였다. 하지만 우리 씬은 Camera가 이미 Player의 자식으로서 위치를 자동으로 따라가므로(참고 스크립트의 `FollowPlayer()`처럼 수동 Lerp 추적을 할 필요가 없고, 오히려 `CharacterController.Move()`와 완전히 동기화되어 지연이 없음), `CameraPivot`(회전 담당) → `Main Camera`(충돌 회피로 위치만 보정) 2단 구조로 단순화했다. 스크립트는 회전의 주체인 `CameraPivot`에 부착해 `transform`이 곧 피벗이 되도록 했다.
9. **범위 제외 사항 명시**: 참고 스크립트의 LockOn(`isLockedOn`, `LockOnTarget`), Q/E 타겟 전환(`HandleTargetSwitching`), 마우스 기반 pitch 조작(`cameraSensitivity`, `cameraMinPitch/MaxPitch`, `CameraInput`)은 이번 계획에 포함하지 않았다. `Look` 액션은 `PlayerInput.inputactions`에 이미 정의되어 있으나 `InputManager`가 구독하지 않는 상태를 그대로 유지한다.
10. **코딩 컨벤션 준수**: 모든 필드/메서드에 접근 제어자 명시, `var` 미사용, `!` 대신 `== null`/`== true` 형태의 명시적 비교 사용(`if (isHit == true)`, `if (_x == null) { return; }`), 클래스/메서드/public 프로퍼티에 한국어 `<summary>` XML 주석 작성. `ForwardDirection`은 블록 바디 `get { ... }`로 작성해 람다식(`=>`) 사용 여부에 대한 모호함을 피했다(사용 근거 주석이 필요 없도록 함).
