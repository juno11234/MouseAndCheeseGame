# 고양이 AI (System: 고양이 AI / Feature: 플레이어 추격 - Path Replay) 구현 계획

- 작성 날짜: 2026-09-19 (26_0919)
- 작성자: planner (Claude Code)
- 요청 범위: Notion GDD에 정리된 아래 설계를 구현한다 (사용자가 프롬프트로 직접 전달한 요약, Notion 재조사 불필요). 1·2·4번은 `!주석`으로 사용자가 직접 수정한 내용이 반영된 최신 버전이다.
  1. **경로 재생(Path Replay) 방식**: 플레이어가 지나간 이동 경로를 기록했다가 고양이가 그 경로를 그대로 따라간다. 플레이어가 실제로 통과 가능했던 곳만 고양이도 통과하므로 구조적으로 불공정한 캐치가 없다. **NavMesh는 사용해도 되지만, 플레이어를 향한 최단 경로로 추격해서는 안 된다(불합리).**
     - 위치는 **프레임 기반**으로 기록하되, 고양이와의 거리가 멀수록 적게(드물게), 가까울수록 자주 기록한다.
     - 평소에는 기록된 경로만 따라가고, 플레이어와의 **직선거리**가 일정 이상 가까워졌을 때에만 고양이가 플레이어를 목표로 직접 추격한다.
     - 직접 추격 중 플레이어가 속도를 높여 다시 멀어지면 경로 추적 상태로 돌아오며, 이때는 **상태가 바뀐 이후에 기록된 경로만** 따라간다.
  2. **가구 등반 기능은 구현하지 않는다.** 다만 풀잎으로 가구 위에 올라간 플레이어가 점프로 이동해 넘어갈 수는 있으므로, **NavMesh에 고양이가 점프할 수 있는 지점(링크)을 지정해 두고** 고양이가 그 링크를 이용해 추격하게 한다.
  3. **풀잎 비행 구간 예외 처리**: 비행 시작 직전 갭을 기록 → 비행 중 고양이는 완전히 정지(전혀 움직이지 않음) → 착지 후 고양이 속도를 일시적으로 조절해 갭을 비행 시작 전 기록값으로 복원(비행이 갭에 순수하게 중립적 효과를 갖도록).
  4. **갭 0 → 게임오버**: 갭이 0이 되면 게임오버 UI를 띄울 예정이지만 이번 단계에서는 구현하지 않는다(이벤트 발생까지만). **갭과 배고픔을 별도로 연동할 필요는 없다.**
  5. **갭 최대치 + 러버밴딩**: 갭이 너무 크게 벌어지면 고양이가 일시적으로 가속해 따라붙는다.
  6. 장애물 충돌로 배고픔이 깎이는 것도 궁극적으로 갭에 영향을 준다(배고픔=속도 통합 스탯이므로).
- 배경(기획 의도, Notion에 이미 정리됨): 위 요청 범위와 동일. 이 프로젝트는 배고픔=이동속도 통합 스탯 게임이라는 전제가 있다(`HungerController` 기존 구현, 1-2절 참고). 직전 "풀잎 비행" Feature(26_0918 계획)가 이번 Feature를 위한 훅(`Player.OnMoveStateChanged` 이벤트)을 미리 만들어 두었다(1-1절 참고).
- 인접 Feature와의 경계(이번 계획에서 직접 구현하지 않음, 아래 6절 근거와 함께):
  - **"게임오버/리스타트" Feature** → 갭이 0이 되면 게임오버 UI를 띄울 예정이라는 것까지만 확정됐고(사용자 지시), 코드베이스 전체에 `GameManager`류 스크립트나 게임오버 처리 로직이 전혀 없음도 확인했다(1-5절). 이번 계획은 갭이 0 이하가 되는 순간 `CatController.OnGapDepleted` 이벤트를 한 번 발생시키는 것까지만 책임지며, UI 표시·화면 전환·재시작·스코어 확정 등은 그 Feature가 이 이벤트를 구독해 수행해야 한다.
  - **"갭/배고픔 UI" Feature** → 갭과 배고픔을 별도로 연동할 필요는 없다(사용자 지시). 이미 존재하는 간접 연동(배고픔이 낮을수록 `HungerController.CurrentMoveSpeed`가 느려지고 → 플레이어가 프레임당 덜 움직이고 → 고양이와의 갭이 그만큼 덜 벌어지거나 더 빨리 좁혀짐)만 그대로 두고, 직접적인 수치 변환 코드는 작성하지 않는다. `CatController.Gap`/`OnGapChanged` 프로퍼티·이벤트만 노출해 향후 UI 등이 폴링·구독할 수 있게 한다(`HungerGaugeUI`/`FlightTimeRatio` 선례와 동일한 패턴).
  - **가구 등반** → 구현할 계획이 없다(사용자 지시). 따라서 경로에 "특수 동작 이벤트"를 태그하는 확장 구조(이전 버전의 `PathEventType`/`RecordSpecialEvent`/`HandlePathEvent`)는 이번 계획에서 **삭제**했다. 고양이가 가구 위로 넘어가는 방법은 NavMesh 링크(점프 지점)로 대체한다(0-3절).
  - **"플레이어·고양이 스탯 데이터 테이블" Feature** → 고양이 이동 속도/러버밴딩 속도/갭 최대치/초기 갭/직접 추격 전환 거리 등은 이번 계획이 만드는 `CatStatData`가 임시 스텁으로만 보유한다. `PlayerStatData`/`LeafFlightData` 선례와 동일한 패턴이며, 정식 밸런싱 수치 확정은 그쪽 책임이다(0-4절).
  - **"맵 배치/스폰" Feature** → 고양이의 초기 스폰 위치는 이미 `SampleScene.unity`에 배치돼 있는 값(`Cat` 오브젝트, 1-3절 확인)을 그대로 쓰며, 이번 계획은 배치 위치 자체를 건드리지 않는다. 다만 고양이가 NavMeshAgent를 쓰게 되므로 그 위치가 베이크된 NavMesh 위에 있어야 하는 씬 작업이 필요해졌다(4-5절).

## 0. 확정되지 않아 이번 계획에서 임의로 결정하지 않은 사항 (구현 단계 결정 필요)

사용자 지시에 따라 아래 항목은 추측으로 확정하지 않았다. 관련 코드에는 최소한으로 동작하는 임시 처리만 두었고, 정확한 사양은 구현 단계에서 별도로 결정해야 한다.

1. **경로 기록의 세부 사양**: "위치를 프레임 단위로 기록하되 고양이와의 거리가 멀수록 적게, 가까울수록 자주 기록한다"는 방향은 확정(사용자 지시)이지만, 아래는 정해진 바 없어 임시 처리로만 구현했다.
   - (a) 프레임 간격을 정하는 구체적인 매핑: 가까울 때 몇 프레임마다, 멀 때 몇 프레임마다 기록할지, 몇 미터부터 "멀다"로 볼지, 선형인지 곡선인지. 임시로 `PlayerPathRecorder`의 `_nearFrameInterval`(1프레임)·`_farFrameInterval`(10프레임)·`_farDistance`(20m)로 선형 보간하는 자리 표시자만 두었다.
   - (b) 여기서 말하는 "고양이와의 거리"의 기준: 사용자가 명시한 것은 직접 추격 쪽의 "직선거리"뿐이라, 기록 빈도도 같은 직선거리를 쓰는 것으로 가정했다. 갭(경로상 거리)을 써야 한다면 `PlayerPathRecorder.ResolveFrameInterval` 한 곳만 바꾸면 된다.
   - (c) 경로점 버퍼의 크기·길이 제한(오래된 경로점을 언제 폐기할지)은 구현하지 않았다 — 게임 한 판이 충분히 짧다는 전제하에 우선 무제한 `Queue`로 두었다.
2. **갭 최대치·러버밴딩 가속 곡선/수치**: `CatStatData._maxGap`/`_rubberBandSpeed`는 개발 테스트용 임시 플레이스홀더 값이다. 러버밴딩을 "갭이 최대치를 넘으면 고정 배율로 가속"하는 이진 방식으로 최소 구현했으며, 점진적으로 가속하는 곡선(`AnimationCurve` 등)이 필요한지는 정해지지 않았다.
3. **NavMesh 점프 지점(링크)의 배치와 점프 연출**: 가구 등반은 구현하지 않고, 고양이가 가구 위로 넘어가는 방법은 NavMesh 링크(`NavMeshLink`)로 점프 가능 지점을 지정하는 방식으로 하기로 했다(사용자 지시). 현재 프로젝트 상태는 `com.unity.ai.navigation` 패키지(2.0.13)만 설치돼 있고 씬에는 `NavMeshSurface`/`NavMeshAgent`/`NavMeshLink`가 하나도 없으며 베이크된 NavMesh 데이터도 없다(1-7절). NavMesh 베이크(범위, `NavMeshAgent` 반경·높이·점프 가능 높이 등 설정값)는 사용자가 에디터에서 시각적으로 확인해 가며 직접 수행하기로 했으므로(사용자 지시) 이 계획에서 값을 정하지 않는다. 아래는 미확정이라 이번 계획은 코드로 확정하지 않는다.
   - (a) 링크를 어느 가구의 어느 위치에 몇 개 배치할지(레벨 디자인 작업).
   - (b) 링크를 통과할 때의 점프 연출(포물선 이동, 점프 애니메이션 재생 등). 이번 계획은 `NavMeshAgent`의 기본 자동 링크 통과만 사용한다. 연출이 필요하면 `autoTraverseOffMeshLink`를 끄고 별도 구현해야 하며, 그 방식은 정해지지 않았다.
   - (c) 플레이어가 링크로 연결되지 않은 지점에 풀잎으로 착지했을 때(NavMesh상 고양이가 도달할 수 없는 지점) 고양이가 어떻게 행동할지. 이번 계획은 별도 처리를 넣지 않고 `NavMeshAgent`의 기본 동작(도달 불가 목적지면 갈 수 있는 곳까지만 이동)에 맡긴다.
4. **세부 밸런싱 수치 일체**: `CatStatData`의 초기 갭(`_initialGap`), 직접 추격 전환 거리(`_directChaseDistance`), 웨이포인트 도달 허용 오차(`_waypointArrivalTolerance`, `NavMeshAgent.remainingDistance`와 비교하는 값), 갭 보정 허용 오차(`_gapCorrectionTolerance`), 갭 보정 속도(`_gapCorrectionSpeed`)와 0-1절 (a)의 프레임 간격 관련 값 모두 개발 테스트용 임시값이며 실제 수치는 "데이터 테이블" Feature 또는 플레이테스트로 결정해야 한다(`PlayerStatData`/`LeafFlightData` 선례와 동일한 패턴). 경로점 간격이 플레이어 속도·프레임레이트에 따라 달라지므로(6-11절) 도달 허용 오차는 그에 맞춰 조정이 필요할 수 있다.

## 1. 코드베이스 조사 결과

### 1-1. `Player.cs` 현재 상태 — 26_0918 계획서와의 차이 확인
- `Assets/02_Scripts/Player.cs`를 직접 다시 읽어 확인한 결과, 같은 폴더의 `26_0918_풀잎비행_plan.md`가 제안했던 `public PlayerMoveState MoveState => _moveState;` 폴링용 프로퍼티는 실제 최종 코드에 반영되지 않았다. 현재 `Player`가 외부에 공개하는 것은 딱 두 가지뿐이다.
  - `public enum PlayerMoveState { Run, Fly }` (파일 최상단, 클래스 바깥)
  - `public event MoveStateChangedHandler OnMoveStateChanged;` (`newState`를 인자로 전달하는 상태 변경 알림 이벤트)
  - 따라서 이번 계획의 모든 컴포넌트는 `Player`의 현재 상태를 **폴링할 수 없고**, `OnMoveStateChanged` 이벤트를 구독해 상태 변화가 있을 때마다 직접 캐싱해야 한다(4-2절 `PlayerPathRecorder`, 4-4절 `CatController` 모두 이 패턴을 따른다).
- `Player.Update()`는 `switch(_moveState)`로 `ApplyGravity()`(Run)/`ApplyFlying()`(Fly)을 분기하고, `HandleMovement(moveDirection, moveSpeed)`를 호출한다. Run 상태의 `moveSpeed`는 `_hungerController.CurrentMoveSpeed`, Fly 상태는 고정값(`8f`)이다 — 즉 **지상 이동 중에는 배고픔이 낮을수록 플레이어가 느려지고, 비행 중에는 배고픔과 무관하게 일정 속도**라는 사실을 확인했다(6-6절 설계 근거로 사용).
- `Player`는 `[RequireComponent(typeof(CharacterController))]`이고, `HungerController`를 형제 컴포넌트로 `GetComponent`(Awake)한다 — DI 없이 같은 GameObject의 형제 컴포넌트는 `GetComponent`, 다른 계층의 오브젝트는 `[SerializeField]` 인스펙터 연결이라는 기존 관례를 그대로 재확인했다(`CameraController`도 `GetComponentInChildren`).

### 1-2. 배고픔=속도 통합 스탯 시스템 (`Assets/02_Scripts/Hunger/`)
- `HungerController.cs`: `_currentHunger`를 들고 있고, `ChangeHunger(float amount)` 하나로 시간 경과 감소(`Update()`)/장애물·음식 충돌(`OnTriggerEnter` + `IHungerObj`)을 통합 처리한다. `public float CurrentMoveSpeed => _playerStatData.EvaluateMoveSpeed(HungerRatio);`가 이미 존재하며, 캐싱 없이 매 호출 즉시 계산한다(`CameraController.ForwardDirection`과 동일한 컨벤션).
- `IHungerObj`(인터페이스, `HungerObjType`+`Amount`)를 `Food.cs`가 구현하고, 장애물(`trap.prefab` 등)도 태그가 아니라 같은 인터페이스 구현 컴포넌트로 식별된다 — 이번 계획은 이 패턴에 새로 얹지 않고, 대신 "배고픔 변화가 이미 `CurrentMoveSpeed`에 반영되고, 그 속도가 `PlayerPathRecorder`의 프레임당 이동거리에 그대로 반영된다"는 기존 인과 사슬을 그대로 활용한다(요청 범위 6번, 6-6절 근거).
- `HungerController.ChangeHunger`의 XML 주석에 "그 상태에서의 게임오버 판정은 고양이 AI(플레이어 추격) Feature의 책임이다"라는 문구가 이미 있다 — 다만 이번 계획은 그 게임오버 판정을 **배고픔 0 자체가 아니라 갭 0**을 기준으로 둔다(요청 범위 4번, "갭이 0이 되면 게임오버"). 배고픔 0에서의 게임오버 판정 필요 여부는 이번 계획에서 다루지 않는다(요청 범위에 명시되지 않음).

### 1-3. 고양이(`Cat`) 프리팹·씬 배치 현재 상태

### 1-4. 고양이 AI/경로/갭 관련 기존 구현 여부
- `Assets/02_Scripts/` 전체에서 `Cat|고양이|PathReplay|Chase|추격` 패턴으로 검색한 결과, `Player.cs`(이벤트 훅 관련 주석), `Flight/LeafFlightData.cs`, `Hunger/HungerController.cs`, `Hunger/PlayerStatData.cs`의 **주석에서만** 이 Feature를 미리 언급할 뿐, 실제 구현 스크립트는 0건이다. 이번 계획이 이 Feature의 최초 구현이다.

### 1-5. 게임오버/GameManager류 시스템 존재 여부
- `Assets/02_Scripts/` 전체를 조사했으나 `GameManager`, `GameOver`, 씬 전환/재시작을 다루는 스크립트가 전혀 없다. 따라서 갭 0 시점의 실제 게임오버 처리는 구조적으로 이번 계획 범위 밖일 수밖에 없다(요청 범위 4번 근거).

### 1-6. DI/아키텍처 패턴 재확인
- DI 프레임워크/Singleton/ServiceLocator 없음. 같은 GameObject의 형제 컴포넌트는 `Awake()`에서 `GetComponent<T>()`, 다른 GameObject(다른 계층)의 참조는 `[SerializeField]` 인스펙터 연결 — 이번 계획의 모든 신규 컴포넌트도 이 두 규칙을 그대로 따른다(`PlayerPathRecorder`의 `Player`와 `CatController`의 `NavMeshAgent`는 전자, `PlayerPathRecorder`의 `_catTransform`과 `CatController`의 `_player`/`_pathRecorder`/`_catStatData`는 후자).
- 이벤트는 전부 커스텀 델리게이트(`public delegate void XxxHandler(...)`) + `OnEnable`/`OnDisable` 대칭 구독 패턴 — `System.Action`/`UnityEvent`는 코드베이스 어디에도 쓰이지 않는다. 이번 계획도 `System.Action` 대신 커스텀 델리게이트만 사용한다.

### 1-7. NavMesh 관련 현재 상태 (이번 `!주석` 반영을 위해 추가 조사)
- `Packages/manifest.json`에 `"com.unity.ai.navigation": "2.0.13"`이 이미 설치돼 있다 — `NavMeshSurface`/`NavMeshLink` 컴포넌트를 쓸 수 있고, 별도 패키지 설치는 필요 없다.
- `Assets/` 전체에서 `NavMeshSurface|NavMeshAgent|NavMeshLink|NavMeshModifier|OffMeshLink|NavMeshData`를 검색한 결과, 매치는 `SampleScene.unity` 한 곳(`m_NavMeshData: {fileID: 0}`, 씬 기본 NavMeshSettings 블록)뿐이다 — 즉 **씬에 NavMesh 관련 컴포넌트가 하나도 없고 베이크된 NavMesh 데이터도 없다.** NavMesh를 쓰려면 베이크와 컴포넌트 부착이 모두 새로 필요하다(4-5절).

### 4-2. `PlayerPathRecorder.cs` (신규)

```csharp
using System.Collections.Generic;
using UnityEngine;

/// <summary>
/// Player의 위치를 프레임 단위로 기록해 고양이가 따라갈 경로점 큐와 갭 계산용 누적 이동 거리를 제공하는 클래스. Player와 같은 GameObject에 부착한다
/// </summary>
public class PlayerPathRecorder : MonoBehaviour
{
    [SerializeField] private Transform _catTransform;
    [SerializeField] private int _nearFrameInterval = 1;
    [SerializeField] private int _farFrameInterval = 10;
    [SerializeField] private float _farDistance = 20f;

    private Player _player;
    private readonly Queue<Vector3> _pathQueue = new Queue<Vector3>();
    private Vector3 _lastPosition;
    private float _totalPathDistance;
    private int _framesSinceLastRecord;
    private PlayerMoveState _cachedMoveState = PlayerMoveState.Run;

    /// <summary>
    /// 게임 시작 후 Player가 실제로 이동한 누적 거리(비행 중 이동분 포함)
    /// </summary>
    public float TotalPathDistance => _totalPathDistance;

    /// <summary>
    /// 큐에 남은 경로점 개수(디버깅용)
    /// </summary>
    public int QueuedPointCount => _pathQueue.Count;

    /// <summary>
    /// 참조와 위치 기준값을 초기화한다
    /// </summary>
    private void Awake()
    {
        _player = GetComponent<Player>();
        _lastPosition = transform.position;
    }

    /// <summary>
    /// Player 이동 상태 변경 이벤트를 구독한다
    /// </summary>
    private void OnEnable()
    {
        _player.OnMoveStateChanged += HandleMoveStateChanged;
    }

    /// <summary>
    /// 이벤트 구독을 해제한다
    /// </summary>
    private void OnDisable()
    {
        _player.OnMoveStateChanged -= HandleMoveStateChanged;
    }

    /// <summary>
    /// 누적 이동 거리를 갱신하고, Run 상태에서 고양이와의 거리로 정한 프레임 간격마다 현재 위치를 큐에 추가한다
    /// </summary>
    private void Update()
    {
        float frameDistance = Vector3.Distance(transform.position, _lastPosition);
        _totalPathDistance += frameDistance;
        _lastPosition = transform.position;

        if (_cachedMoveState != PlayerMoveState.Run)
        {
            return;
        }

        _framesSinceLastRecord++;
        if (_framesSinceLastRecord >= ResolveFrameInterval())
        {
            _pathQueue.Enqueue(transform.position);
            _framesSinceLastRecord = 0;
        }
    }

    /// <summary>
    /// 고양이와의 직선거리가 멀수록 긴 프레임 간격, 가까울수록 짧은 프레임 간격을 반환한다(0-1절)
    /// </summary>
    private int ResolveFrameInterval()
    {
        float distanceToCat = Vector3.Distance(transform.position, _catTransform.position);
        float ratio = Mathf.Clamp01(distanceToCat / _farDistance);
        return Mathf.RoundToInt(Mathf.Lerp(_nearFrameInterval, _farFrameInterval, ratio));
    }

    /// <summary>
    /// 가장 오래된 경로점을 꺼낸다. 큐가 비어 있으면 false를 반환한다
    /// </summary>
    public bool TryDequeueNextPoint(out Vector3 point)
    {
        if (_pathQueue.Count == 0)
        {
            point = default;
            return false;
        }

        point = _pathQueue.Dequeue();
        return true;
    }

    /// <summary>
    /// 큐에 쌓인 경로점을 전부 버린다
    /// </summary>
    public void ClearQueue()
    {
        _pathQueue.Clear();
    }

    /// <summary>
    /// 이동 상태를 캐싱한다. Fly 중에는 경로점을 기록하지 않는다
    /// </summary>
    private void HandleMoveStateChanged(PlayerMoveState newState)
    {
        _cachedMoveState = newState;
    }
}
```

### 4-4. `CatController.cs` (신규)

```csharp
using UnityEngine;
using UnityEngine.AI;

/// <summary>
/// 고양이의 추격 상태. Chasing(경로 추격), DirectChasing(플레이어 직접 추격), Frozen(비행 중 정지), GapCorrecting(착지 후 갭 보정), Caught(포획)
/// </summary>
public enum CatState
{
    Chasing,
    DirectChasing,
    Frozen,
    GapCorrecting,
    Caught
}

/// <summary>
/// 기록된 경로를 NavMeshAgent로 따라가며 플레이어를 추격하고, 갭·러버밴딩·풀잎 비행 갭 중립화·게임오버 트리거를 처리한다. Cat GameObject에 부착한다
/// </summary>
[RequireComponent(typeof(NavMeshAgent))]
public class CatController : MonoBehaviour
{
    public delegate void GapChangedHandler(float gap);
    public delegate void GapDepletedHandler();

    [SerializeField] private Player _player;
    [SerializeField] private PlayerPathRecorder _pathRecorder;
    [SerializeField] private CatStatData _catStatData;

    private NavMeshAgent _agent;
    private CatState _state = CatState.Chasing;
    private Vector3? _currentTarget;
    private Vector3 _lastPosition;
    private float _catTraveledDistance;
    private float _gapSnapshotAtFlightStart;
    private bool _hasGapDepleted;

    /// <summary>
    /// 갭이 갱신될 때마다 발생하는 이벤트
    /// </summary>
    public event GapChangedHandler OnGapChanged;

    /// <summary>
    /// 갭이 0 이하가 되면 한 번 발생하는 이벤트(게임오버 트리거)
    /// </summary>
    public event GapDepletedHandler OnGapDepleted;

    /// <summary>
    /// 플레이어와 고양이 사이의 경로상 거리(플레이어 누적 이동 거리 - 고양이 누적 이동 거리)
    /// </summary>
    public float Gap => _pathRecorder.TotalPathDistance - _catTraveledDistance;

    /// <summary>
    /// 플레이어와의 직선거리
    /// </summary>
    private float DistanceToPlayer => Vector3.Distance(transform.position, _player.transform.position);

    /// <summary>
    /// NavMeshAgent를 설정하고 초기 갭을 반영한다
    /// </summary>
    private void Awake()
    {
        _agent = GetComponent<NavMeshAgent>();
        _agent.autoBraking = false;
        _lastPosition = transform.position;
        _catTraveledDistance = -_catStatData.InitialGap;
    }

    /// <summary>
    /// Player 이동 상태 변경 이벤트를 구독한다
    /// </summary>
    private void OnEnable()
    {
        _player.OnMoveStateChanged += HandlePlayerMoveStateChanged;
    }

    /// <summary>
    /// 이벤트 구독을 해제한다
    /// </summary>
    private void OnDisable()
    {
        _player.OnMoveStateChanged -= HandlePlayerMoveStateChanged;
    }

    /// <summary>
    /// 누적 이동 거리를 갱신하고 상태별 추격 동작을 수행하며, 갭이 0 이하가 되면 Caught로 전환하고 OnGapDepleted를 발생시킨다
    /// </summary>
    private void Update()
    {
        TrackTraveledDistance();

        switch (_state)
        {
            case CatState.Frozen:
            case CatState.Caught:
                return;
            case CatState.Chasing:
                FollowRecordedPath(ResolveChasingSpeed());
                if (DistanceToPlayer <= _catStatData.DirectChaseDistance)
                {
                    SetState(CatState.DirectChasing);
                }
                break;
            case CatState.DirectChasing:
                ChasePlayerDirectly();
                if (DistanceToPlayer > _catStatData.DirectChaseDistance)
                {
                    SetState(CatState.Chasing);
                }
                break;
            case CatState.GapCorrecting:
                FollowRecordedPath(_catStatData.GapCorrectionSpeed);
                if (Mathf.Abs(Gap - _gapSnapshotAtFlightStart) <= _catStatData.GapCorrectionTolerance)
                {
                    SetState(CatState.Chasing);
                }
                break;
        }

        OnGapChanged?.Invoke(Gap);

        if (Gap <= 0f && _hasGapDepleted == false)
        {
            _hasGapDepleted = true;
            SetState(CatState.Caught);
            OnGapDepleted?.Invoke();
        }
    }

    /// <summary>
    /// 이번 프레임에 실제로 이동한 거리를 고양이 누적 이동 거리에 더한다
    /// </summary>
    private void TrackTraveledDistance()
    {
        _catTraveledDistance += Vector3.Distance(transform.position, _lastPosition);
        _lastPosition = transform.position;
    }

    /// <summary>
    /// 갭이 MaxGap을 넘으면 러버밴딩 속도, 아니면 기본 속도를 반환한다
    /// </summary>
    private float ResolveChasingSpeed()
    {
        return Gap > _catStatData.MaxGap ? _catStatData.RubberBandSpeed : _catStatData.MoveSpeed;
    }

    /// <summary>
    /// 큐의 다음 경로점을 목적지로 지정하고, 도착하면 다음 경로점을 소비할 수 있게 목표를 비운다
    /// </summary>
    private void FollowRecordedPath(float speed)
    {
        _agent.speed = speed;

        if (_currentTarget.HasValue == false && _pathRecorder.TryDequeueNextPoint(out Vector3 next))
        {
            _currentTarget = next;
            _agent.SetDestination(next);
        }

        if (_currentTarget.HasValue == false)
        {
            return;
        }

        if (_agent.pathPending == false && _agent.remainingDistance <= _catStatData.WaypointArrivalTolerance)
        {
            _currentTarget = null;
        }
    }

    /// <summary>
    /// 플레이어의 현재 위치를 목적지로 직접 추격한다
    /// </summary>
    private void ChasePlayerDirectly()
    {
        _agent.speed = _catStatData.MoveSpeed;
        _agent.SetDestination(_player.transform.position);
    }

    /// <summary>
    /// 상태를 바꾸고 NavMeshAgent 정지 여부를 맞춘다. 직접 추격 상태를 떠날 때는 큐와 현재 목표를 비워, 이후에는 상태가 바뀐 뒤 기록된 경로만 따르게 한다
    /// </summary>
    private void SetState(CatState newState)
    {
        if (_state == CatState.DirectChasing && newState != CatState.DirectChasing)
        {
            _pathRecorder.ClearQueue();
            _currentTarget = null;
        }

        _state = newState;

        bool shouldStop = newState == CatState.Frozen || newState == CatState.Caught;
        _agent.isStopped = shouldStop;
        if (shouldStop)
        {
            _agent.velocity = Vector3.zero;
        }
    }

    /// <summary>
    /// Fly가 되면 갭을 기록하고 정지, Run으로 돌아오면 갭 보정을 시작한다. Caught 이후에는 무시한다
    /// </summary>
    private void HandlePlayerMoveStateChanged(PlayerMoveState newState)
    {
        if (_state == CatState.Caught)
        {
            return;
        }

        if (newState == PlayerMoveState.Fly)
        {
            _gapSnapshotAtFlightStart = Gap;
            SetState(CatState.Frozen);
        }
        else
        {
            SetState(CatState.GapCorrecting);
        }
    }
}
```

### 4-5. Unity Editor 수동 작업 (코드 외 작업)

1. `CatStatData` 에셋 1개를 임시로 생성(우클릭 → Create → MouseAndCheese → Cat Stat Data).
2. `SampleScene.unity`의 `Player` GameObject에 `PlayerPathRecorder` 컴포넌트를 추가하고, `_catTransform`에 `Cat` 오브젝트의 Transform을 인스펙터에서 연결한다(다른 GameObject라 인스펙터 연결이 필요하다). 프레임 간격 관련 3개 값(`_nearFrameInterval`/`_farFrameInterval`/`_farDistance`)은 기본값을 임시로 사용한다.
3. **NavMesh 준비**(1-7절: 현재 씬에 NavMesh 관련 요소가 전혀 없음): `NavMeshSurface` 컴포넌트 추가와 베이크는 사용자가 에디터에서 시각적으로 확인해 가며 직접 수행한다(사용자 지시). 베이크 범위와 `NavMeshAgent` 반경/높이 등 세부 설정값은 이 계획에서 정하지 않는다(0-3절).
4. **점프 지점 배치**: 풀잎으로 올라간 가구 위에서 플레이어가 점프해 넘어갈 수 있는 구간마다, 고양이가 따라 넘을 수 있도록 `NavMeshLink`를 배치한다. 위치·개수는 레벨 디자인 작업이며 미확정이다(0-3절 (a)). 점프 연출은 기본 자동 통과 그대로 둔다(0-3절 (b)).
5. `SampleScene.unity`의 `Cat` GameObject에 `NavMeshAgent`와 `CatController` 컴포넌트를 추가하고, `_player`(Player GameObject), `_pathRecorder`(Player GameObject의 PlayerPathRecorder), `_catStatData`(1번에서 만든 에셋)를 인스펙터에서 연결한다. `Cat`의 시작 위치가 베이크된 NavMesh 위에 정확히 놓여 있어야 한다 — 벗어나 있으면 `NavMeshAgent`가 생성에 실패하거나 시작 시점에 표면으로 스냅되면서 그 이동량이 누적 이동 거리에 섞여 초기 갭이 어긋난다(현재 배치값 `(-19.16, 10.89653, 15.04)`가 NavMesh 위에 있는지는 베이크 후 확인 필요).
6. `Player.prefab`/`Cat.prefab` 자체에도 위 컴포넌트를 미리 부착해 둘지(프리팹 단위로 적용) 여부는 씬 배치 방식(SampleScene 전용인지, 다른 씬에도 재사용하는지)에 따라 구현 단계에서 결정한다 — 이번 계획은 최소 동작 확인을 위해 씬 인스턴스 기준으로만 안내한다.

## 6. 주의 사항 및 설계 결정 근거

1. **기존 코드 파일을 전혀 수정하지 않는 이유**: `Player.cs`가 이미 `OnMoveStateChanged` 이벤트를 공개하고 있어, 그 이벤트를 구독하는 두 신규 컴포넌트(`PlayerPathRecorder`, `CatController`)만으로 요청 범위 3번(풀잎 비행 예외 처리)을 전부 구현할 수 있었다. 다만 26_0918 계획서가 제안했던 `MoveState` 폴링 프로퍼티가 실제로는 구현되지 않았다는 사실을 확인했으므로(1-1절), 이번 계획의 두 컴포넌트는 상태를 폴링하지 않고 이벤트로 전달받은 값을 각자 캐싱하는 방식으로 설계했다. `HungerController.cs`도 마찬가지로 손대지 않았다(6-6절 근거).
2. **갭을 "두 개의 누적 이동 거리(오도미터) 차이"로 설계한 이유**: 매 프레임 두 캐릭터 사이의 직선/경로 거리를 다시 계산하는 대신, 각자 "자신이 실제로 걸은 거리"를 독립적으로 누적하고 그 차이를 갭으로 정의했다. 이렇게 하면 (a) 갭이 정확히 "경로상 거리"라는 요청 범위 정의와 일치하고, (b) 풀잎 비행처럼 한쪽만 멈추는 상황을 "그 쪽의 누적값만 멈춘다"는 아주 단순한 규칙 하나로 자연스럽게 표현할 수 있으며, (c) 큐에 쌓인 경로점 전체를 매 프레임 순회해 길이를 합산할 필요가 없어 성능상으로도 유리하다. 고양이의 누적 거리는 이동 방식(경로 추격/직접 추격/NavMeshLink 통과)과 무관하게 `NavMeshAgent`가 실제로 움직인 거리만 더하므로(`TrackTraveledDistance`), NavMesh를 도입해도 이 정의는 그대로 유지된다.
3. **비행 중 오도미터(`TotalPathDistance`)는 멈추지 않고, 경로점 큐만 멈추는 이유**: "비행 시작 직전 갭을 기록해 두고 착지 후 그 값으로 복원한다"는 요청 범위 3번의 문구 자체가, 비행 중 갭이 실제로 변한다는 것을 전제로 한다(변하지 않는다면 애초에 기록해 둘 필요가 없다). 플레이어는 비행 중에도 실제로 전진하므로 오도미터는 계속 누적되어야 하고(갭이 자연스럽게 벌어짐), 고양이는 완전히 정지(`Frozen`)하므로 자신의 누적값은 그대로다 — 그 결과로 벌어진 갭을 착지 후 `GapCorrecting` 상태가 되돌린다. 반면 경로점 큐는 "고양이가 물리적으로 걸어갈 수 있는 지상 경로"만 담아야 하므로, 하늘을 가로지른 구간은 애초에 점으로 남기지 않는다(26_0918 계획서의 "Path Replay는 비행 구간을 경로 이벤트로 기록하지 않는다"는 결정과 정확히 일치).
4. **러버밴딩과 풀잎 비행 갭 보정을 별도 상태로 분리한 이유**: 둘 다 "고양이를 평소보다 빠르게 움직인다"는 점에서 비슷해 보이지만 목표가 다르다. 러버밴딩(`Chasing` 내부의 속도 분기)은 갭이 `MaxGap`이라는 **상한선**을 넘었을 때만, 그 상한선 아래로 내려올 때까지 발동하는 문턱 기반 로직이다. 반면 풀잎 비행 갭 보정(`GapCorrecting`)은 `MaxGap`과 무관하게 **비행 시작 직전 기록해 둔 정확한 값**을 목표로 하는 일회성 로직이다(그 값이 `MaxGap`보다 작을 수도 크게 클 수도 있으므로 문턱 로직으로는 표현할 수 없다). 두 로직을 하나로 합치면 "비행 후엔 항상 MaxGap까지만 좁혀지고 그 이하로는 안 돌아간다"는 의도치 않은 동작이 생길 수 있어 분리했다.
5. **갭과 배고픔을 별도로 연결하는 코드를 만들지 않은 이유**: 사용자가 갭↔배고픔을 별도로 연동할 필요는 없다고 확정했으므로, `HungerController.ChangeHunger`를 갭 쪽에서 호출하는 코드를 만들지 않았다. 이미 존재하는 간접 인과관계(배고픔 → `CurrentMoveSpeed` → 플레이어의 프레임당 이동거리 → 오도미터 증가폭 → 갭)만 그대로 남는다. `Gap`/`OnGapChanged`는 갭 UI 등 다른 Feature가 쓸 수 있도록 노출만 해 둔다.
6. **장애물 충돌이 갭에 영향을 주는 경로도 별도 코드 없이 성립함을 확인**: `HungerController.OnTriggerEnter`가 장애물과 충돌하면 `ChangeHunger(amount)`(음수)를 호출하고, 이는 `CurrentMoveSpeed`를 즉시 낮춘다(1-2절). `Player.HandleMovement`는 매 프레임 이 값을 그대로 쓰므로, 장애물에 맞은 직후 플레이어의 프레임당 이동거리가 줄고, 그만큼 `PlayerPathRecorder`의 오도미터 증가폭도 줄어 갭이 상대적으로(고양이는 자기 속도 그대로이므로) 좁혀진다. 5번과 같은 이유로 이 경로에도 새 코드를 추가하지 않았다.
7. **경로점 큐를 단일 소비자(고양이 한 마리) 전용 구조로 설계함**: `PlayerPathRecorder.TryDequeueNextPoint`는 호출할 때마다 큐에서 항목을 제거하는 파괴적 소비 방식이다. 현재 게임에 고양이가 한 마리뿐이라는 전제(1-3절, GDD 요약 어디에도 다중 고양이 언급 없음) 하에는 문제가 없지만, 향후 고양이가 여러 마리로 늘어나면 각자 독립적인 "읽기 커서"가 필요해지므로 파괴적 `Dequeue` 대신 인덱스 기반 커서 구조로 바꿔야 한다 — 이번 계획은 그 확장을 하지 않았다(요청 범위에 다중 고양이 언급 없음, 미확정 사항 0절에도 명시하지 않은 이유는 애초에 요청 범위가 고양이 한 마리를 전제하기 때문).
8. **고양이 이동에 `NavMeshAgent`를 쓰고 `CharacterController`/중력/직접 `Transform` 이동은 쓰지 않는 이유**: 이전 버전은 `Vector3.MoveTowards`로 경로점 사이를 직선 이동했는데, 이 방식은 (a) 풀잎 비행 착지 후 비행 전 마지막 경로점에서 착지 지점 사이를 직선으로 가로질러 고양이가 공중을 지나가거나 가구를 뚫고 가게 되고, (b) 가구 위로 넘어가는 점프 구간을 표현할 수단이 없다. `NavMeshAgent`는 경로점 사이를 NavMesh 표면을 따라 이동하고(중력 시뮬레이션 불필요), `NavMeshLink`로 지정된 점프 지점을 통과할 수 있어 사용자 지시(`!주석`)의 "NavMesh로 고양이가 점프할 수 있는 곳을 지정해두고 추격"과 일치한다. 에이전트가 표면에 붙어 이동하므로 `Cat.prefab`에 Collider/Rigidbody는 여전히 추가하지 않는다. 이동 방향으로의 회전도 `NavMeshAgent`의 기본 동작(`updateRotation`)이 처리하므로 별도 회전 코드를 두지 않는다. `Awake`에서 `autoBraking`을 끄는 이유는, 경로점 간격이 촘촘해 켜 두면 경로점마다 감속해 고양이가 멈칫거리기 때문이다.
9. **특수 동작 이벤트 구조(`PathEventType`/`RecordSpecialEvent`/`HandlePathEvent`)를 삭제한 이유**: 이전 버전은 "가구 등반 등 특수 동작을 경로점에 태그로 남긴다"는 확장 지점을 빈 구현으로 남겨 뒀지만, 사용자가 가구 등반 자체를 구현하지 않기로 했고 가구 위로 넘어가는 동작은 NavMesh 링크(점프 지점)가 대신 처리한다(0-3절). 실제로 호출될 일이 없는 확장 지점을 남겨 두면 코드만 복잡해지므로 삭제했고, 그에 따라 경로점이 위치 외에 담을 정보가 없어져 `PathPoint`도 `Vector3`로 단순화했다.
10. **평소엔 경로만 따르고 가까울 때에만 직접 추격하는 이유**: 처음부터 플레이어를 향한 최단 경로로 추격하면(`SetDestination(플레이어)`) 플레이어가 돌아간 곳을 고양이가 가로질러 지름길로 잡게 되어 Path Replay의 핵심 전제("플레이어가 통과했던 곳만 고양이도 통과한다", 요청 범위 1번)가 깨지고 불합리한 추격이 된다(사용자 지시). 반면 아주 가까워졌을 때는 경로점을 하나하나 밟는 것과 플레이어에게 곧장 가는 것의 차이가 거의 없으므로, 그 구간에서만 직접 추격을 허용한다. 전환 판정은 플레이어와의 **직선거리** 기준이다(사용자 확정, `DirectChaseDistance` 수치는 임시값 — 0-4절). 직접 추격 중 플레이어가 속도를 높여 다시 멀어져 경로 추적 상태로 돌아오면 **그 상태가 바뀐 이후에 기록된 경로만** 따라가야 하므로(사용자 확정), 직접 추격 상태를 떠날 때 큐와 현재 목표를 비운다(`SetState`). 직접 추격 중에는 경로점을 소비하지 않기 때문에, 비우지 않으면 이미 지나온 오래된 경로점으로 되돌아가게 된다.
11. **경로점을 프레임 기반으로, 고양이와의 거리에 따라 기록 빈도를 바꿔 쌓는 이유**: 사용자 지시("프레임 기반으로 위치를 기록, 고양이와의 거리가 멀수록 적게, 가까울수록 자주")를 그대로 따랐다. 이 방식의 결과로 경로점 간격은 플레이어 속도·프레임레이트에 따라 달라지므로(이전 버전의 고정 0.5m 거리 기반과 다름) `WaypointArrivalTolerance` 같은 수치는 그에 맞춰 조정이 필요할 수 있다(0-4절). 플레이어가 멈춰 있어도 같은 위치가 프레임 간격마다 계속 큐에 쌓이는데, 이 부분을 걸러내는 처리는 요청에 없어 넣지 않았다.
12. **코딩 컨벤션 준수**: 모든 필드/메서드에 접근 제어자 명시, `var` 미사용(타입 항상 명시), `!` 대신 `== false` 사용, 클래스·public 멤버·private 메서드에 한국어 `<summary>` XML 주석 작성(핵심 한 줄), 람다식 미사용(사용한 곳 없음), 이벤트는 `System.Action` 대신 기존 관례와 동일한 커스텀 델리게이트(`GapChangedHandler`/`GapDepletedHandler`)로 선언했다(1-6절 근거). `_catTransform`/`_catStatData`/`_player`/`_pathRecorder` 등 필수 참조가 인스펙터에 연결되지 않으면 `NullReferenceException`이 그대로 발생하도록 두는 fail-fast 방식을 유지했다(디버깅용 null 체크를 넣지 않는다는 규칙, `HungerController`/`LeafFlightTrigger`의 기존 결정과 동일). `NavMeshAgent`는 `[RequireComponent]`로 보장하므로 `GetComponent` 결과에 null 체크를 넣지 않는다.
